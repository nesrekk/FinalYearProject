# NBA Hub

A full-stack NBA analytics platform built as a final-year project: real historical data (1950 through the current season for career/season stats; 2009-10 through the current season for the deepest advanced-stat coverage), trained and backtested prediction models, era-normalized player comparison engines, a live betting-market cross-reference, real play-by-play win-probability modeling, and a suite of stat-driven daily games — all built on top of one PostgreSQL database (plus an optional read-only cloud mirror — Layerbase, full parity including shot charts/play-by-play — for remote/cloud sessions) and served through three FastAPI microservices to a React dashboard.

The project's guiding rule, followed throughout: **never fabricate data**. Where a real number exists, it's used and its source is traceable to a real endpoint or a real database column. Where the project doesn't have real data for something (player height/wingspan, a trade-history dataset, a real referee-bias claim), that gap is disclosed in the UI rather than invented — several features explicitly say what they *aren't*, and small real samples get an explicit warning instead of being presented as comprehensive.

## For an AI assistant picking this project up

Read this whole section before touching anything. It exists so you don't need the owner to re-explain context that's already been established over many previous sessions.

**Environment gotchas — get these wrong and everything else breaks:**
- Plain `python3` on this machine resolves to an Anaconda install missing this project's dependencies. Always use `/Library/Frameworks/Python.framework/Versions/3.14/bin/python3` explicitly, for every script run and every `pip install`.
- Each of the three API files has its own `if __name__ == "__main__"` uvicorn fallback port, but **always pass `--port` explicitly anyway** — don't rely on the fallback, and don't assume the fallback is correct (it has been wrong before and gets fixed reactively; the ports the frontend actually calls are the ones in `frontend/src/services/api.js` — currently 8000/mvp, 8001/similarity, 8002/impact).
- DB credentials live in `api/.env` (gitignored) as `DB_HOST`/`DB_PORT`/`DB_USER`/`DB_PASSWORD`/`DB_NAME`, read through `api/db_config.py` and `scripts/db_config.py` (two separate small modules, each resolving `api/.env` by an absolute path so they work regardless of current working directory). Every script and service does `from db_config import DB_CONFIG`. **Never hardcode the password back into a file** — it used to be hardcoded everywhere and was deliberately pulled out; the old password is still in git history from before that cleanup, so treat it as not-really-secret and don't reuse it for anything real.
- Postgres DB name: `nba_analytics`.
- `DB_TARGET` in `api/.env` picks local (default, always use for dev), `layerbase` (a full-parity Postgres mirror — every table including `player_shots`/`pbp_events`, see the Layerbase entry near the bottom of the Roadmap section), or `cloud` (the older Supabase read mirror, missing `player_shots`/`pbp_events` due to its 500MB free-tier cap — kept for now, but Layerbase is the one with full parity). If you ever need to refresh a cloud copy after local data changes meaningfully: `cd scripts && python3 migrate_to_layerbase.py` (full drop-and-reload per table, chunked streaming for the two big tables, recreates non-PK indexes too) or `python3 migrate_to_supabase.py` for the Supabase copy (no `pg_dump`/`psql` needed or available on this machine, either way).
- Scripts are normally run as `cd scripts && python3 whatever.py` (their docstrings say so), but don't assume — check the top of the script; some things (like the test suite) are written to work from any cwd.
- `nba_api` hits the real stats.nba.com over the network. It's rate-limit-sensitive: existing fetch scripts use `time.sleep()` between calls (0.4–1.0s for reliable endpoints like `PlayByPlayV3`/`LeagueGameFinder`, more conservative 5–30s backoff for the flakier `shotchartdetail` endpoint) plus retry-with-backoff. Match the existing pattern in whichever script is closest to what you're building; don't invent a new rate-limiting scheme.
- Season encoding: `player_season_stats.season` and most other tables use the **end year as an int** (e.g. `2026` means the 2025-26 season). Convert to the NBA's own label format with `f"{season - 1}-{str(season)[-2:]}"` when calling `nba_api` — this exact expression appears throughout the codebase, copy it rather than reinventing it. `pbp_games`/`pbp_events` now span real seasons 2021-2026 (previously just one sampled season, see C8 below) and agree with `player_season_stats`'s latest season — but still query each table's own `MAX(season)` rather than assuming any two tables agree on "the latest season" (this exact bug was found and fixed once already in `/games/wp-replay/list`, back when they didn't).

**The "never fabricate data" rule in practice — how to apply it to new work:**
- A composite/index metric (Heliocentricity Index, Impact Score) is fine as a simple, fully-disclosed equal-weighted average of real percentile ranks. It is never presented as a trained/validated model unless it actually is one.
- A predictive/simulated feature (e.g. "what would this trade do to team chemistry") needs either a real trained model with real validation metrics, or it gets scoped down to something that only uses real data that actually happened (see Lineup Chemistry below — the honest substitute for a "Trade Chemistry Simulator" that would have needed an invented usage-redistribution formula).
- Every "what if" / counterfactual feature (see Game Replay) must say in its own API response and its own UI copy that it's a counterfactual, not a prediction of what actually would have happened.
- Small real samples get a disclosed warning/cutoff (e.g. Playoff Drop-off Forecaster's `small_sample_warning` under 10 games, Lineup Chemistry's `min_minutes` cutoff with `lineups_qualified`/`lineups_total` both returned) rather than being silently included or silently hidden.
- If a feature needs data the project doesn't have (a real API key, a real dataset), say so to the owner directly and ask, rather than fabricating placeholder data or silently declining. Registering third-party accounts / submitting signup forms with the owner's info is an action that needs the owner's explicit go-ahead, not something to do autonomously.

**Verification discipline expected on every feature before it's considered done:**
1. Test the actual data source (nba_api endpoint, SQL query, whatever) directly with real inputs *before* writing application code around it — this has caught real bugs early several times (empty-string score fields that needed forward-filling, a `CalibratedClassifierCV` API quirk, non-unique `action_number` values).
2. Run the backend, `curl` the new endpoint(s), confirm real data and the expected JSON shape.
3. Start the frontend dev server, actually click through the new UI in the browser pane (`preview_start` with name `nba-frontend`), check the browser console for errors, screenshot if it's visual.
4. Run the smoke tests: `/Library/Frameworks/Python.framework/Versions/3.14/bin/python3 -m pytest api/tests` (works from repo root or `api/`). Add a test for any new endpoint.
5. Do a real "sniff test": does a leaderboard/ranking match genuine basketball knowledge? (e.g. DeMar DeRozan's real reputation as a clutch scorer landing near the top of the Clutch WPA leaderboard was treated as evidence the whole WPA pipeline was working.)
6. `git status --short` and a `grep` for any literal secret values across changed files, every time, before staging — `api/.env` must never get committed (it's gitignored; verify with `git check-ignore -v api/.env` if in doubt).

**Commit style:** one commit per feature, detailed message explaining what's real about it and what was verified, ending with `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>` (or whichever model actually did the work — check the current session's own attribution instructions rather than assuming). Only commit when the owner asks; `git status` and read the diff before staging.

## What's in it

**Core stats & browsing**
- **Shareable links** (`frontend/src/utils/useUrlState.js`) — the open page is in the URL (`?page=builder`), so a reload, a bookmark or a pasted link opens the same page, and Back/Forward move between pages. Seven tools also keep their inputs in the link and have a **Copy link** button: Leaderboard Builder (`stat`, `from`, `to`, `gp`, `mpg`, `att`, `team`, `order`, `n`), its Build-your-own-metric mode (`mode=metric&w=pts:1,ts_pct:2` plus the same filters), Regression Explorer (`x`, `y`, seasons, floors, `within=0`), Breakout Detector (`season`, `dir`, `stats`, floors, `n`), Player Comparison (`season`, `a`, `b`), Shot Charts (`player`, `season`, `view=heatmap`) and Trade Analyzer (`season`, `ta`/`pa`, `tb`/`pb`; a full trade runs by itself on open). Changing an input rewrites the link without adding history entries; a value that's missing or no longer valid falls back to the default. Analytics tabs keep their `#hash`.
- **Player profile page** (`?page=player&id=<NBA person id>`, `pages/PlayerProfile.jsx`, `GET /player-profile/{id}`) — one linkable page per player, opened by clicking any player's name or photo (`PlayerName`), a player result in the Ctrl+K search, or **Open full profile** in the player modal (the modal stays). Header: photo, bio (position, height, weight, birth date, college, Hall of Fame; Basketball-Reference), draft pick, last team, latest role (`player_roles`) and Greats of the Game entry. Then, each only when that player has data: season-by-season table (a traded season lists games per team; seasons under 10 games greyed), awards and honours (every MVP / DPOY / ROY / Sixth Man / MIP / Clutch POY vote finish, All-NBA / All-Defense / All-Rookie teams and All-Star selections, 1946-47 on), shot zones by season against the league (regular season, `league_zone_mix`) plus the Shot mix over a career chart, the Exploit Guide scouting report, DAD Index defense, Gravity, contract value, clutch WPA, the five most similar seasons by other players (similarity service, looked up by player id), and Breakout Detector flags (same ranking as that page, with a link to the list). Whatever a player lacks is listed under **Not on file** with the reason (e.g. matchup tracking starts in 2017-18; salary data starts in 2005-06), never shown as an empty box. Every block carries its season and sample size; **Copy link** shares the profile.
- **Team page** (`?page=team&abbr=<code>&season=<end year>`, `pages/TeamProfile.jsx`, `GET /team-profile/{abbr}?season=` in `api/routers/team_profile.py`) — the team twin of the player profile, for every team-season 1946-47 to 2025-26. `abbr` takes any code a team has used (PHX or PHO, BKN/BRK/NJN) or its franchise's current code; a franchise plus a season it played under another name opens that team with a note (OKC + 2005 = the 2004-05 SuperSonics). Blocks, each stating its coverage and, when empty, listed under "Not on file" with the reason: season summary (record, Pythagorean record, margin, SRS/SOS, ORtg/DRtg/pace, the four factors on both ends, league averages and ranks among that season's teams; Basketball-Reference, every season), franchise history chart (win % every season, playoffs marked, click to open), game by game (margin chart, last 10 or all games, home/away and rest records; 2009-10 on, real scores), luck & schedule (2009-10 on), roster with roles and part-season rows for traded players (from 2020-21 the play-by-play decides who played for whom, and players the season rows list under a team they never played for are named as left out), payroll and best/worst contract value (salary seasons only), best/worst stored five-man lineups with minutes coverage and a Pair Chemistry link (2013-14 on), on/off leaders and the top-usage player (2020-21 on), and shot mix vs. the league for the team and its opponents (1996-97 on). New tables: `team_seasons` (`scripts/build_team_seasons.py`, franchise map in `api/teams_lib.py`) and `team_zone_mix` (`scripts/build_team_zone_mix.py`). Every team logo/name in Standings, the dashboard standings, Team Comparison, Ctrl+K team results, the player profile (hero chip and season table), Game Log, Game Finder, On/Off, Luck & Schedule's team history, Player Stats, Stat Leaders, Lineup Chemistry and Schedule Fatigue links to it through `common/TeamLink.jsx` (with the season where the table has one). Smoke test.
- **Watchlist** (`utils/watchlist.js`, `?page=watchlist`) — click the star next to a player's name anywhere `common/PlayerName.jsx` renders it to add or remove them; the list lives in `localStorage` only (per-browser, nothing sent to the server). The Watchlist page shows each starred player's most recent season's PTS/REB/AST/STL/BLK/TS%/Net Rtg side by side (`GET /players/history/{name}`, the same endpoint Trend Analysis uses), exports to CSV/JSON, and stays in sync live everywhere the star appears via `useSyncExternalStore`.
- **Saved analyses** (`utils/savedViews.js`, `?page=saved`) — a **Save** button next to every tool's **Copy link** button (Leaderboard Builder incl. its Build-your-own-metric mode, Regression Explorer, Breakout Detector, Player Comparison, Shot Charts, Trade Analyzer, Trade Impact, Stat Stability, Stat Line Finder, Era Translator, Role Player Finder, Pair Chemistry, and the player profile) saves the exact current URL — page, tab and every input already in the query string — with an auto title (the tool's nav label plus its inputs, or the player's name on a profile). Saves live in `localStorage` only, nothing server-side. The Saved page lists them newest first with an editable title and note, **Open** (loads the exact saved view via a new `openFullUrl()` in `utils/useUrlState.js`, which replays the URL verbatim rather than rebuilding it), **Delete**, and JSON **Export**/**Import** (import merges by URL, so re-importing the same file twice never duplicates a row).
- **Chart export + hover tooltips** (`utils/chartExport.js`, `common/ChartExport.jsx`, `utils/useChartCrosshair.js`, `common/ChartTooltip.jsx`) — every hand-built SVG chart with real data (about 35 charts across ~28 components) gets a **PNG**/**SVG** download button: it walks the live, rendered SVG with `getComputedStyle` and writes every element's actual paint (fill, stroke, opacity, stroke-width/dasharray, font) back as an explicit attribute before serializing, since this app's colors come from CSS custom properties and stylesheet classes that mean nothing in a file opened outside the app — verified by exporting a chart and confirming zero `var(--...)` or `class=` left in the file; PNG renders the same markup through a canvas at 2x with the current theme's page background painted first, so nothing is transparent. Decorative/non-data SVGs (icon previews, sparkline accents, the Learn-the-Game court diagrams, Guess the Game) are left out on purpose. A shared `useChartCrosshair` hook adds nearest-point hover (mouse move anywhere over the plot area, not a precise hit on a 2-3px dot) plus keyboard support (Tab to focus, Left/Right/Home/End to step through points) to seven time-series charts that had no tooltip at all or only an exact-circle one: Trend Analysis, Stat Stability's reliability curve, Era Translator's pace chart, the Game Log rolling-average chart, and Projections' backtest-by-season chart got the full hook; Trajectory Forecaster and Game Replay's win-probability line keep their own layered hover (band/line/point regions that a single nearest-x overlay would break) but gained keyboard focus. Charts with an existing working hover (Schedule Fatigue's rest chart, Shot Mix, Shot-making) kept their own interaction and just got the export button. No new table, no backend change.
- Live scores, standings, full player-stats browser with sortable/filterable tables
- **Stat Line Finder** (Players menu, `?page=statline`, `GET /similarity/stat-line?line=pts:25,ts_pct:0.6,ast:8&season=` on the similarity service, options at `/similarity/stat-line/options`) — type a stat line (any of 16 stats, up to 10: per-game box score, 3P%/FT%/TS%, usage, assist %, rebound %, net rating, minutes, age) and get the closest real player-seasons. Same idea as Season Similarity's matrix (each stat z-scored within its own season over every player-season that has it), but the typed line is read as a standing in a season the user picks, and matches are ranked by the root-mean-square gap in z-scores on the typed stats only (levels, not cosine shape). Shooting percentages use the Leaderboard Builder's attempts floors; each stat is usable from its first well-recorded season (same catalogue; a smoke test checks they agree). The page echoes the line (season average, standing, n), shows every match's values with its gap per stat and what drives the distance, greys seasons under 40 games, warns when nothing is within one standard deviation, has example lines, a season range, games floor and one-per-player toggle, and a shareable link (`line`, `season`, `from`, `to`, `gp`, `one`, `n`). Sniff tests: Curry 2015-16's, LeBron 2012-13's and Wilt 1961-62's own lines return those seasons at distance 0; 3 blocks + 12 rebounds today gives Olajuwon, Camby, Mutombo, Wembanyama, Robinson.
- **Game Log + Game Finder** (`api/routers/game_log.py`: `GET /games/player-log/{id}?season=`, `GET /games/finder`, options at `/games/finder/options`, player search at `/games/finder/players`) — every regular-season player-game 2020-21 to 2025-26 (`player_game_lines`, rebuilt from ESPN play-by-play; there is no game-level data before 2020-21 and both pages say so). The **player profile** gets a Game log block: every game he played in a chosen season (date, opponent, home/away, result and margin, minutes, box line, TS%, days of rest / back-to-back), newest first, with a hand-built SVG chart of one stat game by game plus its 5- or 10-game rolling average (shooting % are ratios of the window's totals) against the season average, and a warning when the play-by-play has a different number of games than NBA.com lists. **Game Finder** (Players menu, `?page=gamefinder`): up to 8 stat conditions (`f=pts:gte:30,fga:lt:15`; 19 stats incl. minutes, FG%, 3P%, FT%, TS%), season range, team, home/away, team result, minimum minutes and one player; sortable, paginated (25-200 a page), CSV/JSON export, copy link. Streak mode finds the longest runs of games in a row that all meet the conditions (gaps-and-islands over each player's games that pass the other filters; games he sat out don't break a run, runs can cross seasons; longest per player or every run; an Active tag when it's still going at his last game on file). Opponent, result and rest come from `team_game_fatigue`, joined on (team, date) because ESPN game ids aren't NBA ids; that join also leaves out the three NBA Cup finals (they don't count in regular-season stats or the standings), which the pages list. Filters are whitelisted (stat keys, operators, sort keys, teams), values are bound parameters. No new table. Checked against real box scores: Dončić's 73 (25-33 FG, 8-13 3P, 15-16 FT, 10 reb, 7 ast), Embiid's 70 (24-41, 21-23 FT, 18 reb), Mitchell's 71 in overtime (22-34, 7-15 3P, 20-25 FT, 11 ast), Lillard's 71 (22-38, 13-22 3P), Curry's 56 at Orlando (12-19 3P); streaks: Curry's 11 straight 30-point games (Mar 29 to Apr 19, 2021) and Embiid's 22 in 2023-24; Jokić's games per season 72/74/69/79/70 = NBA.com's.
- **Hot Streak Checker** (Players menu, `?page=hotstreaks`; `api/routers/hot_streaks.py`: `GET /games/hot-streak/{id}?season=&stat=&window=&as_of=`, `GET /games/hot-streaks`, options at `/games/hot-streak/options`; shared definitions in `api/hot_streaks.py`; `scripts/build_hot_streak_persistence.py` -> `hot_streak_persistence`) — "is his last 5, 10 or 20 games real?" for 14 stats (per-game counts, minutes, FG%/3P%/FT%/TS%, usage), 2020-21 on. Two separate answers: **how unusual** (4,000 random N-game sets from his own season so far; the share at least as hot or cold, plus the run's percentile among his actual stretches) and **how much carries on** (the share of a run's gap from baseline that showed up again in the next N games, measured on every player-season window 2020-21 to 2025-26). Baseline = this season's games before the run plus his previous season (`player_season_stats`) counted as a set number of games, chosen per stat and window on held-out seasons (half a season to a whole one for 3P%/TS%/FT%, 10-20 games for points and usage). On the **player profile** it's a card inside the Game log (same stat and window as the chart, any as-of date, and what he actually did next when there are later games); the **league page** ranks everyone's run as of a date by how far it sits from his own random sets, greys p >= 0.05, shows minutes before and during (role changes), counts how many would look significant by chance alone, and, for a past date, what the listed players did next. Findings: shooting runs are mostly noise (3P% keeps 8/12/28% of a 5/10/20-game gap; as of January 15 of three seasons, 9-11 players had a significant 10-game 3P% run against 9.6-10.8 expected by chance); minutes (56/66/77%), usage and points carry on far more. Stat Stability's between-player reliability isn't used for this: for points it would say 90% of a 5-game run lasts, against 34% measured. Methodology card added.
- **Situational Splits** (Players menu, `?page=splits`; `api/routers/situational_splits.py`: `GET /splits/situational/leaderboard?season=&split=&stat=&sort=`, `GET /splits/situational/player/{id}?season=`, options at `/splits/situational/options`; shared definitions in `api/situational_splits.py`; `scripts/build_situational_splits.py` (~80 s) -> `player_situational_splits`, `situational_split_league`) — every player-season 2020-21 on, four splits: home vs. away, back-to-back (second nights he also played the first night of) vs. 1+ days of team rest, 1,000+ miles traveled vs. under 300, that season's top-10 vs. bottom-10 teams by final-score margin (`game_scores`); 11 stats (minutes per game; points, rebounds, assists, steals, blocks, turnovers, 3PA per 36; TS%, 3P%, usage). Each gap has a game-clustered 95% interval and is shown against the **average player's gap** that season (weighted mean, team-season bootstrap). The honesty checks are on the page: how many players stand out against how many do when each player's own games are shuffled between the two sides, and the year-to-year correlation of a player's gap. On the **player profile** it's a block with every stat for a chosen season and split (greyed within noise, a Repeats column). Findings: home court +0.23 points per 36 and +0.9 TS points (smallest in fan-less 2020-21); top-10 opponents cost 1.09 points per 36 and 2.2 TS points; players who play both nights of a back-to-back get 0.65 more minutes and shoot the same (stars rest); 41 of 44 split/stat year-to-year correlations are under 0.1, so individual splits are mostly noise. Travel is confounded with home court (long trips end at home 38% of the time, short ones 77%): the page also shows the effect with home/away held equal. Methodology card added.
- **Breakout Detector** (Players menu, `GET /explore/breakouts?season=&direction=up|down&stats=`) — the biggest season-over-season rises or drops in a player's standing within the league: each chosen stat (default points, TS%, usage, assist %, rebound %, BPM; up to 8) is z-scored within its season among players with 30+ games and 15+ minutes, and the score is the average change in standing from the season before (both seasons must qualify). Every row shows each stat before → after with its change in standing. A historical line measures regression to the mean with the same stats and filters: the 20 biggest breakouts of each season 1978-79 to 2024-25 kept a median 73% of their jump the next year (847 players; 59% for three-point stats alone). Sniff test: 2016-17 breakouts include Giannis (that year's Most Improved Player), Jokić and James Johnson; declines are led by Chandler Parsons and Curry after his unanimous MVP season.
- **Stat Stability** (Players menu, `?page=stability`, `GET /leaderboard/stability`, `scripts/build_stat_stability.py`) — "when does a stat mean something": for every Leaderboard stat, the sample at which a player's number is half his own level and half luck. Split-half reliability: each player-season's games split into odd and even, both halves cut at the same sample (attempts, games, possessions, rebound chances...), centred by season, correlated across players; Spearman-Brown gives reliability = n / (n + M) and M is fitted over every sample size with 100+ player-seasons (bootstrap 95% range). Data: new `player_game_lines` (every regular-season game 2020-21 to 2025-26, rebuilt from ESPN play-by-play including minutes from substitutions: season totals within 0.3% of NBA.com's, three-point attempts included since 2026-09-29, minutes within 0.3% on average) and every stored shot since 1996-97 for FG%/3P%/eFG%. Results: 3P% needs 476 attempts (95% range 420-531; a typical rotation season of 155 attempts is 0.25 reliable), FT% 27 attempts, rebound % 51 chances, TS% 208 shooting attempts, net rating about 1,000 possessions; per-game counting stats settle in a game or two (minutes and role barely change), so they also get a per-minute version (points per minute: 48 minutes; steals: 289). Year-to-year correlation for every stat alongside (the only measure for BPM/VORP/impact score): 3P% 0.39, rebound % 0.96. Table + reliability curve (hand-built SVG), shareable (`stat`, `v=per_minute`). Fed back: the Leaderboard Builder adds a Reliability column and greys rows under 0.5 (e.g. 20 of 2025-26's top 25 3P% seasons), and the Breakout Detector marks stat changes where either season's sample is under 0.5 (`api/stat_samples.py` turns season totals into the same sample units).
- **Era Translator** (Players menu, `?page=era&player=&season=&to=`, `api/routers/era.py`: `GET /era/translate?player_id=&season=&target=`, `GET /era/players?q=`) — restates any player-season 1949-50 to 2025-26 in another season's environment, two ways side by side: **pace only** (each per-game count × target league pace ÷ source league pace; percentages unchanged) and **pace + league** (each count × target ÷ source league average per team game for that stat, i.e. the same share of an average team's output, which for points folds in scoring efficiency; percentages shifted by the change in league average; threes stay pace-only). Plus the era-free comparison: z-score, percentile and rank within the player's own season among 30+ game, 20+ minute players (the builders' attempt floors for shooting %). League pace chart with estimated seasons dashed, a small-sample warning under 30 games or 20 minutes, CSV/JSON export, Copy link. League data: `scripts/build_league_averages.py` → `league_season_averages` (80 seasons, Basketball-Reference league-average rows; pace for 1950-51 to 1972-73 is Basketball-Reference's estimate, and 1949-50 plus the BAA seasons are estimated here from FGA + 0.44 × FTA × 0.994, the 1950-51 to 1952-53 ratio). - **Clutch-Time Win Probability Added (WPA) Tracker** — a real trained Logistic Regression win-probability model (same library/approach as the MVP/DPOY/ROY models), fit on real play-by-play from two real sources (`scripts/fetch_play_by_play.py` for nba_api, `scripts/fetch_pbp_espn.py` for real full-season ESPN coverage via sportsdataverse → `train_wpa_model.py` → `compute_wpa.py`), isotonic-calibrated, held out by *game* (not by row) to avoid leakage — 7,232 unique real games across seasons 2021-2026 (each real game counted once: the 420 nba_api games that ESPN also has are dropped in favor of the ESPN copy, `wpa_lib.PBP_DEDUP_WHERE`), real held-out ROC-AUC 0.830 (0.850 clutch-time-only) on 1,447 held-out games. - **Clutch vs. non-clutch** (Analytics › Clutch WPA, under the leaderboard; `GET /players/clutch-split?min_clutch_chances=50|100|200`) — does a player do better or worse in clutch time than in the rest of the game? A clutch play swings win probability 3.7× as much as an average play, so raw per-play WPA would call almost everyone clutch; `compute_wpa.py` divides each play's WPA by its leverage (the win-probability value of one point at that moment, from the same model: (WP(margin+2) − WP(margin−2)) / 4) and sums as a ratio, Σ WPA / Σ leverage, which puts it in points at equal leverage. Rates are per scoring chance (a shot, free throw or turnover), since rebounds, fouls and substitutions earn ~0 WPA and would mix usage into the rate. Clutch lift = clutch rate − non-clutch rate − the league's own change (0.843 vs 0.914 points per chance), with a 95% interval clustered by game (delta method for a ratio). Stored in new `player_wpa_totals` columns (`nonclutch_wpa`, `nonclutch_plays`, `clutch_chances`, `nonclutch_chances`, `clutch_pts_rate`, `nonclutch_pts_rate`, `clutch_lift`, `clutch_lift_se`) and a one-row `wpa_clutch_league`. The page leads with the honest result: with 100+ clutch chances, 6 of 186 players are better and 8 worse at 95%, where about 9 would clear the bar by chance alone. The model doesn't know who has the ball, so a miss or turnover costs nothing: this measures scoring, not defense.

- **Garbage-Time Deflator** (`scripts/build_leverage_splits.py`, `GET /players/garbage-time`, `GET /players/garbage-time/player/{id}`) — splits every real player's real production by how much the game was on the line when it happened. Every real play in ESPN's full-season play-by-play gets a **Leverage Index**: the expected absolute win-probability swing of the next play at that game state (seconds left × score margin before the play), from the project's own deployed WPA model and the real league-wide mix of scoring outcomes, scaled so the average real play is exactly 1.0. Plays are bucketed garbage (pre-play WP > 99% either way, or 2nd half/OT with margin ≥ 18) → high (LI ≥ 1.5 or NBA clutch time) → low (LI < 0.3) → medium, first match wins (garbage is checked before clutch on purpose; ~17% of real NBA-clutch plays are already >99% decided, and that count is shown). - **Luck & Schedule** (Teams & Markets → Luck & Schedule, `?page=analytics#luck`; `GET /teams/luck-schedule?season=&as_of=`, `/teams/luck-schedule/model`, `/teams/luck-schedule/team/{abbr}` in `api/routers/luck_schedule.py`; math shared with the script in `api/luck_lib.py`) — every team-season 2009-10 to 2025-26 from the real final score of every regular-season game (`game_scores`, `scripts/fetch_game_scores.py`, ESPN's scoreboard matched to NBA game ids; season points for/against equal Basketball-Reference's for all 510 team-seasons). Expected wins from points (Pythagorean, exponent 13.94 fitted on all team-seasons; beat a normal curve and a straight line in margin on leave-one-season-out error, 3.06 wins vs. 3.15/3.25), luck = actual − expected wins, records in games decided by ≤3 / ≤5 points and in overtime, and SRS/SOS (least-squares ratings with a home-court term per season, neutral-site games including the 2020 bubble get none). An **as-of date** (or the Halfway button) refits everything on the games before that morning, shows each team's remaining schedule strength and projects the rest (ratings shrunk toward average by the share of their spread that's noise, each game a win chance with that season's home court and game SD), next to what actually happened. Click a team for its franchise's luck in every season (NJN/BKN and NOH/NOP joined). A scatter of expected vs. actual win% for all 510 team-seasons shows the fit, and a checks table answers "does luck carry over?" (`scripts/build_luck_schedule.py` → `team_luck_schedule`, `luck_schedule_seasons`, `luck_model_fit`, `luck_schedule_validation`; the router caches them per process: restart impact_api after rerunning either script). Honest result: luck mostly doesn't carry (franchise luck correlates 0.14 with next season's, 95% interval 0.05-0.22, vs. 0.59 for margin), but the small part that repeats is clear of zero, and next season's win% correlates about equally with this season's record (0.600) and expected win% (0.605). Methodology card; smoke test.
- **Gravity Index & Spacing Lab** (`scripts/fetch_spacing_data.py` → `scripts/build_gravity_index.py`, `GET /spacing/gravity`, `GET /spacing/lineup`) — a **disclosed composite proxy** for shooting gravity (not player-tracking gravity, which needs raw defender coordinates this project doesn't have), 2013-14 through 2025-26. Three real components, each z-scored within the season against 500+ minute players and summed: 3PA per 100 possessions; catch-and-shoot 3P%; and the share of 3PA taken with a defender within 6 ft (the NBA's own closest-defender bands). The last two are shrunk with a 250-attempt prior toward the real rate of players with similar 3-point volume that season — a disclosed departure from the plan's "shrink to the league mean", made because the league-mean prior rated non-shooters as average (Rudy Gobert, 0 3PA in 2024-25, landed above a fifth of real shooters; after the change he's at the 7.5th percentile and Stephen Curry at the 99.7th). Tracking data covers 98.8–99.8% of real box-score 3PA every season. Lineup spacing = the five players' summed Gravity. The Spacing Lab lets you pick any five players and shows their spacing percentile among that season's real 100+-possession lineups, a half-court drawn to real court dimensions and tinted by that percentile (labeled as a visualization of the index, not player positions), whether those five really played together (and their real ORtg), and a predicted ORtg change vs. a median-spacing lineup — only when the validation is significant **and** the lineup's spacing is within the range of real lineups that season (the five highest-Gravity players sum to ~+26, far beyond any real lineup's ~+15, so that combination gets an explicit "outside real data" message instead of an extrapolated number). **Real validation:** 4,256 real 5-man lineups with 100+ possessions: weighted least squares of real ORtg on lineup spacing + the five players' summed OBPM + season fixed effects, standard errors clustered by team-season (390 clusters; `scripts/stats_lib.py`, checked by simulation — reported SE 0.0618 vs. empirical 0.0615, 96% CI coverage). Result with Basketball-Reference's OBPM (2026-09-27): +0.074 ORtg per spacing point (95% CI 0.014–0.134, p = 0.016); R² 0.3595 vs. 0.3586 without spacing — a small effect (25th→75th percentile spacing ≈ +0.4 ORtg). With the old in-house OBPM it was +0.163 (p ≈ 2e-6): better-measured lineup quality absorbed about half of what looked like a spacing effect. Sniff test: the real 2024-25 Knicks starting five scores +5.82 (81st percentile), predicted +0.3 (95% CI +0.06 to +0.6) vs. a median lineup; their real ORtg together was 117.7 over 1,939 possessions.
- **Contract Value ("Moneyball Engine")** (`scripts/load_salaries.py` → `scripts/build_contract_value.py`, `GET /contracts/value`, `GET /contracts/player/{id}`) — real production priced in dollars vs. real salary, for 2005-06 through 2016-17, 2018-19, 2019-20 and 2024-25. Fair value = max(WAR, 0) × that season's real cost per win + the real league minimum; surplus = fair value − real salary. **Cost per win** = (real salaries of the players who actually played − players × the real 0-years league minimum) ÷ (real league wins − what .200 teams would win), from real salaries, real team records (`Team Summaries.csv`) and the real CBA minimum salary (sourced per season from Larry Coon's CBA FAQ and Hoops Rumors, stored with its source in `league_minimum_salary`) — $2.08M/win in 2005-06 up to $6.11M in 2024-25, never assumed. **WAR** = VORP × 2.7 (Basketball-Reference's conversion) on Basketball-Reference's published VORP, then rescaled per season so positive WAR sums to the real wins above replacement (raw positive WAR sums to 1.25–1.31× them; scale factor 0.77–0.80, shown in the UI). With the old in-house VORP that ratio was 1.27–2.00× and priced 2024-25 SGA at a $279M "fair value", which is how the reproduction's problem was first spotted. Only players who actually played are priced (see Known real gaps for why). UI (Teams & Markets → Contract Value): the season's cost per win with its full real calculation, a salary-vs-WAR scatter with the fair-value line, Top 10 bargains (500+ minutes), Top 10 cap liabilities (paid $25M+), and a methods drawer; the Trade Analyzer also shows both traded players' real salary, WAR, fair value and surplus when the season has salary data. "Rookie-scale years" is labeled only from real draft data (first-round pick, seasons 1–4). **Checks:** salaries matched to real players for 96.8–100% of each included season's real minutes (seasons under 90% are excluded — 2017-18, at 88.2%, is missing LeBron, Durant and others in the source file). Sniff test: the biggest bargain of 2015-16 is Stephen Curry (unanimous MVP on $11.4M, +$45.1M surplus); 2019-20's top bargains after Giannis Antetokounmpo are rookie deals (Luka Dončić, Jayson Tatum, Pascal Siakam, Bam Adebayo); 2024-25's worst liabilities are Bradley Beal, Joel Embiid and Paul George.
- **Trade Impact** (Teams menu, `?page=tradeimpact`; `GET /trade/impact`, `api/routers/trade_impact.py`) — one screen for a 1-for-1 trade, before and after for both teams: projected win% and wins from the Trade Analyzer's model (minute-weighted roster net rating + TS%; players carry their own season stats, so role and minutes changes aren't simulated), starting-five spacing from the Gravity Index summed over each team's most-used real five-man lineup (the incoming player takes the outgoing player's spot, or the lowest-minute starter's spot if the outgoing player wasn't in that five; the page says which rule applied), and priced payroll and contract surplus from Contract Value (players with matched salaries who played for the team; not the cap sheet). Nothing new is estimated. Each block states its coverage (wins 2009-10 onward, spacing 2013-14 onward, payroll 2005-06 to 2016-17, 2018-19, 2019-20 and 2024-25) and shows the reason instead of zeros when a season lacks it; 2024-25 is the latest season with all three. The Spacing Lab's lineup logic moved into `spacing_lab.lineup_report()` so both endpoints share it, and Trade Analyzer and Trade Impact hand a trade to each other through link parameters (`onNavigate(page, hash, params)`). Exportable "both sides at a glance" table; Methodology card. Sniff test (2024-25): the Knicks' most-used five is their real starting five (Towns, Anunoby, Hart, Bridges, Brunson; 1,939 possessions, 117.7 ORtg), the roster model projects them at 51.4 wins (they won 51), and Josh Hart for Duncan Robinson lifts that five's spacing from the 81st to the 97th percentile (+5.96 on the index) while New York's priced payroll moves by the real salary gap (+$1.26M) and its surplus by −$45.6M (Hart +$28.6M vs. Robinson −$17.0M).
- **Game Win-Probability Replay** — replays one real game's entire real play-by-play through the same real WPA model, charting home win probability over the whole game (top 5 real plays by |WPA| marked, hover for details), plus a clickable "what if this real missed shot had gone in" counterfactual (dashed line) that recomputes the rest of the game's win probability assuming the shot's points landed and every later real play happened exactly as it did — clearly labeled as a counterfactual, not a re-simulation.
- **With vs. Without a Star** — pick a real team, season, and player: real record, win%, and average point differential split by whether that real player actually played in each real game that season, live-fetched from the NBA's own full-season game logs. Labeled explicitly as a real association, not a causal claim (other absences in the same games aren't controlled for) — a real sniff test on the 2023-24 Sixers/Embiid split (79.5% win rate with him vs. 37.2% without, across 39 and 43 real games) reproduces that season's well-documented real storyline exactly.
- **Schedule Fatigue** — real rest days, real back-to-backs, real travel miles (haversine between each real consecutive game's real arena location, `scripts/arenas.py`), and real time zones crossed for every real team-game 2010-2026 (`scripts/build_schedule_fatigue.py`, 40,696 real rows). A real win%-by-rest-bucket study (44.4% on 0 real rest days vs. 51-53% on 1-3, a clean real reproduction of the NBA's well-documented back-to-back fatigue effect) and a real team schedule-difficulty ranking by total real travel miles. Live Scores also gets real "B2B" / rest-disadvantage tags per team, computed from this same real stored schedule.
- **Referee Tendencies** — real officials (`BoxScoreSummaryV2`) matched to the real fouls/FTA/pace each of their real games produced (`LeagueGameFinder`), season-adjusted against the real league average for those same real seasons, with a real 95% confidence interval on the difference (`scripts/fetch_referee_officials.py`, `scripts/build_referee_tendencies.py`). Deliberately descriptive, not diagnostic: it compares real games-called totals to a real baseline and says nothing about cause — crew assignment, opponent style, and era are real, unmeasured confounders — and officials under 25 real games worked are explicitly flagged as a small sample rather than ranked alongside officials with a real full season on file. `fetch_referee_officials.py` is a real one-call-per-game pipeline (nba_api has no bulk officials endpoint) — resumable and safe to re-run; it skips every game_id it has already attempted, so real coverage grows each time it's run rather than needing to finish in one sitting. A **By Official / By Crew** toggle (`GET /referees/crew-tendencies`, `referee_crew_tendencies`) groups the same real games by the exact real 3-official crew that worked them (games with any other official count excluded so crew identity stays unambiguous) and runs the identical season-adjusted comparison per crew. **Honest finding, not a data gap:** real crew assignments are close to random from game to game — of 5,373 real distinct 3-official crews across 2021-2026, only 514 ever worked together more than once (max 4 real games), so the small-sample flag (below 10 real games together) applies to nearly every crew; any single crew's numbers are a curiosity about that handful of real games, not a reliable tendency estimate.

*College & Draft*
- Draft Prospect Comp Finder — ~105,000 real D1 college player-seasons (CollegeBasketballData.com), era-normalized, matched by name to real NBA rookie outcomes wherever a real match exists (~55% of NBA rookies since 2015 — international/G-League/draft-and-stash players never appear in US college data). Optional "include measurements" toggle adds real wingspan-minus-height and real standing reach (NBA Draft Combine, `scripts/fetch_draft_combine.py`, 1133 real player-measurements 2010-2026) to the comp vector, narrowing to real combine attendees only. A **"Does Length Matter?"** card real-correlates wingspan-minus-height against real career-average DBPM and real steals+blocks per 36 (n=565, Pearson r shown, scatter plot) — a real, weak-to-moderate positive correlation, not a causal claim. Real body measurements also show in the Player Comparison profile when a player has them on file.
- **College → NBA Pipeline** — every NBA pick 2013-2025 who came from a US college (613 of 615; one junior-college pick and Shaedon Sharpe, who never played a college game, are left out), linked to that college team's season in Bart Torvik's ratings (national rank, opponent-adjusted efficiency margin, NCAA tournament run), and to Basketball-Reference Win Shares in the first four NBA seasons against a draft-slot expectation (`WS4 = 17.42 − 3.78 × ln(pick)`, fitted on all 598 picks 2013-2022). Only classes through 2022 (478 college players) have four NBA seasons and get a verdict. **Finding: once you know the pick, college team strength barely matters** — +0.38 WS per +10 points of team margin, 95% bootstrap range −0.30 to +1.04, r = 0.05; every team-rank tier and tournament-run group's interval crosses zero. Picks with no US college come in at −1.41 WS vs. slot (−2.44 to −0.25), mostly the draft-and-stash effect (31% played no NBA games in four seasons vs. 5% of college picks). Also a school table (≥5 picks, with ranges) and a searchable player table with headshots. `scripts/load_college_teams.py` → `scripts/build_college_pipeline.py`, `GET /college/pipeline`, Analytics tab `#pipeline`.
- **March Madness Model** — pre-tournament odds for every NCAA bracket 2013-2026 (no 2020 tournament), from inputs known before the first tip: an opponent- and venue-adjusted scoring margin fitted here (ridge least squares on every D1-vs-D1 game before the tournament, margins capped at ±25), CollegeBasketballData.com Elo going into the tournament, and seed. Logistic regression on the difference between two teams, then 20,000 simulations of the real bracket. Five input sets were compared by leave-one-season-out backtest on 2013-2025 (801 tournament games) and the best held-out log loss was kept: **adjusted margin alone** (log loss 0.557, 70.4% of games called; seeds alone 0.581 / 69.4%; margin+Elo 0.557 / 70.8%; Elo alone 0.597 / 66.8%). Honest result: better-calibrated than seeds game by game (round-by-round log loss 0.216 vs 0.229), but **not better at finding the champion** — the champion was the model's favourite in 2 of 12 backtest seasons and in its top 4 in 7, while it was a 1 seed in 9. **2026 was held back entirely as the final test:** Michigan won; the model had them 3rd (18.9%) before tip-off; it called 71.6% of games vs 72.4% for seeds (same-seed games count as half for seeds), with log loss 0.473 vs 0.517. Torvik's end-of-season ratings are deliberately not used (they include the tournament). `scripts/fetch_cbb_games.py` → `scripts/build_ncaa_model.py`, `GET /college/madness?season=`, Analytics tab `#madness`.

Each service is independent (its own CORS setup, its own DB connection pool built from the shared `db_config.py`) and can be restarted without touching the others. The frontend's `services/api.js` hardcodes which base URL each feature calls. `scripts/wpa_lib.py` is a small shared module (model loading, win-probability scoring, the clutch-time constants, a game-clock-elapsed conversion) imported by both `scripts/compute_wpa.py` and `api/impact_api.py`'s Game Replay endpoints, so there's exactly one real implementation of the win-probability math rather than two that could drift apart.

## Tech stack

- **Backend:** Python, FastAPI, psycopg2, pandas, scikit-learn, scipy, `nba_api`, requests, python-dotenv, pytest + httpx (smoke tests)
- **Database:** PostgreSQL (`nba_analytics`)
- **Frontend:** React 19, Vite, Framer Motion, axios, Lenis (smooth scroll, landing page only), three.js (landing page's 3D shot court only, lazy-loaded) — no charting library; every chart (radar profiles, ROC curves, reliability diagrams, win-probability replay, trajectory cones, archetype scatter plots) is a hand-built SVG component
- **Models & statistics:** Logistic Regression (MVP/DPOY/ROY, ROC/SHAP-validated; win-probability model, isotonic-calibrated), Gradient Boosting comparisons, K-Means clustering (archetypes, offensive styles), cosine similarity (season/career comps), ridge regression (pair synergy), weighted least squares with team-season cluster-robust standard errors (`scripts/stats_lib.py`, Spacing Lab validation — no statsmodels dependency), two-proportion z-tests with Wilson-interval persistence checks (Exploit Guide), method-of-moments variance estimation (Synergy play types), empirical-Bayes shrinkage (Gravity)

## Running it locally

### Prerequisites
- PostgreSQL running locally with a `nba_analytics` database already populated (see `scripts/` for the fetch/build pipeline)
- Node.js for the frontend

### Python interpreter — read this first
```bash
/Library/Frameworks/Python.framework/Versions/3.14/bin/python3 -m pip install fastapi uvicorn psycopg2-binary pandas numpy scikit-learn scipy nba_api requests python-dotenv pytest httpx certifi sportsdataverse rapidfuzz
```
- **macOS only, one-time:** `sportsdataverse` transitively imports `xgboost`, which needs the OpenMP runtime: `brew install libomp`. Without it, `import sportsdataverse` (or anything under `sportsdataverse.nba`) fails with `XGBoostError: Library not loaded: @rpath/libomp.dylib` even though nothing in this project actually calls xgboost.
- **macOS python.org/Python.framework builds only, one-time:** if any live HTTPS fetch (`sportsdataverse`, `nba_api`, the odds/CBBD APIs) fails with `SSL: CERTIFICATE_VERIFY_FAILED`, run `/Applications/Python\ 3.14/Install\ Certificates.command` — the framework build doesn't wire itself up to the system/certifi trust store by default.

### `.env` setup
Create `api/.env` (gitignored):
```bash
DB_HOST=localhost
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=your_local_postgres_password
DB_NAME=nba_analytics

# Optional — see "Optional live data" below
ODDS_API_KEY=your_odds_api_key_here

```


Any backend port already in use is skipped (assumed already running). Tested in a real terminal: all four come up and respond, and Ctrl+C stops all of them with nothing left behind. Local Postgres still has to be running.

Opens at `http://localhost:5173`.

## Established conventions & patterns (follow these, don't reinvent)

- **Era-normalization**: any feature comparing players across seasons z-scores each stat within its own season's qualified pool first (`cluster_players.py`, the similarity engines, the Draft Prospect bridge pool). Never pool raw stat values across eras.
- **Headshots/logos**: `<PlayerHeadshot playerId={} playerName={} size={} />` and `<TeamLogo abbreviation={} size={} />` (both in `components/common/`) — they fail gracefully to initials/a fallback, never a broken image icon.
- **Tooltips**: `<InfoTooltip label="..." title="...">` for any "how does this work" disclosure — the project's standard place to put honest methodology explanations rather than burying them in a modal or leaving them unexplained.
- **Source badges**: every main Analytics endpoint's JSON includes a `_source` object (`api/source_badge.py`'s `make_source(tables, upstream_api, as_of=None, live=False)`) disclosing which real Postgres table(s) backed the response, which real upstream API/dataset those tables came from, and — for the handful of endpoints that live-fetch rather than read a precomputed table — that it's live. The frontend renders it with `<SourceBadge source={data?._source} />` (`components/common/SourceBadge.jsx`) next to the section's `InfoTooltip`; it renders nothing if `_source` is absent, so it's safe to add to a new endpoint at any time without touching the frontend contract.
- **Page links**: pages are listed in `PAGES` in `frontend/src/App.jsx` (ids match `navConfig.js`) and live in `?page=<id>`. Navigate with the `onNavigate(page, hash)` prop App passes to every page (TopNav, CommandPalette, Landing and Methodology use the same function); it pushes a history entry. Never set `window.location.hash` after navigating: pass the Analytics tab as `hash` instead. From components that don't get `onNavigate` (e.g. `PlayerName`), use `openPage(page, params)` / `openPlayerProfile(id)` from `utils/useUrlState.js`; App re-reads the URL on its `nbahub:navigate` event. Link to a player with `<PlayerName>` (it links to the profile by itself) or put `playerProfileHref(id)` on an `<a>` with an `isPlainClick` handler, so cmd-click still opens a new tab.
- **Tool inputs in the link**: read them once when the component sets up its state (`useInitialParams()` + `parseParam.int/num/oneOf/str/list`, each returning null for a missing or bad value so you fall back to the default) and mirror them back with `useUrlSync({ key: value })` (null/''/[] removes a key; pass null while options are still loading). Keep keys short and readable, and add `<CopyLinkButton />` (`components/common/`) to the tool's title row.
- **Analytics tabs**: registered in `TAB_GROUPS` in `frontend/src/components/pages/AnalyticsSection.jsx`, grouped into Models / Player Analysis / Teams & Markets / Prospects. The active tab syncs to `location.hash` via `history.replaceState` (no back-button spam) so any tab is directly linkable, e.g. `http://localhost:5173/#wpa`.
- **Table export**: put `<TableExport />` directly before any new data table (or its `.table-wrapper`); `DataTable` already has it. It reads the rendered table, so there's nothing to wire to the data. Mark decoration inside cells with `data-export-skip`, or give a badge plain words with `data-export-as="..."`. Pass `name="..."` when the nearest heading above the table isn't its title.
- **Live external fetches** in the API layer are cached in an in-process `_CACHE` dict with a TTL (see `impact_api.py`'s `_CACHE`/`_CACHE_TTL_SECONDS`) rather than hitting `nba_api`/external APIs on every request.
- **New feature checklist**: pipeline script in `scripts/` (if new data needed) → Postgres table → endpoint in the right API file (awards/validation → `mvp_api.py`; similarity/clustering → `similarity_api.py`; everything else → a new or existing file under `api/routers/`, sharing helpers from `api/impact_core.py`), with a `_source` object on the response → `fetchXyz()` function in `services/api.js` → `XyzSection.jsx` component with a `<SourceBadge>` → registered in `AnalyticsSection.jsx`'s `TAB_GROUPS` → smoke test → verified in browser → committed.

## Known real gaps (disclosed, not hidden)

- **A few player-seasons carry a team the player never played for (found 2026-09-28, not changed):** from 2020-21 on, 3-5 rows a season in `player_season_stats` list a later team (2024-25: Desmond Bane under ORL, Cole Anthony and Kentavious Caldwell-Pope under MEM, Brandon Ingram under TOR, Maxi Kleber under LAL), checked against the teams in `player_game_lines`. The team page's roster and payroll use the play-by-play's teams and name who was left out; tools that display a player's team from the season row still show the listed one (Methodology open issue). Before 2020-21 there are no per-game teams to check against.
- **`team_game_fatigue.plus_minus` isn't the final margin in 160 games (found 2026-09-28; no stored-data tool reads it since 2026-09-28):** it is stats.nba.com's summed player plus-minus ÷ 5 (values like 33.6), and it differs from the real final score in 160 of 20,348 games 2009-10 to 2025-26 (134 by a point or more; in 109 the two teams' margins don't add to zero, in 13 the sign disagrees with the stored win flag). Wins and losses are right (they match Basketball-Reference for every team-season). The column is kept, but every tool now takes margins from `game_scores` (joined on game_id + team): Luck & Schedule, the team page, Game Log and Game Finder (margin column and sort), Schedule Fatigue's rest study, Team Comparison (recent meetings, last-10 form) and Situational Splits' opponent ranks (plus_minus had tied NYK and DAL for 10th in 2020-21, so that season's "top 10" held 11 teams). Still affected: **With/Without a Star** fetches the same field live from stats.nba.com (`impact_core._fetch_team_game_log`), so its average point differential can be off by a fraction of a point; fixing it means moving it to stored data (team games from `game_scores`, who played from `player_game_lines`, 2020-21 on only). It's on its Methodology card. Separately, the ESPN play-by-play's last score (`team_game_totals.pts_for/pts_against`, used by On/Off) differs from ESPN's own final score in 43 of 7,229 games 2020-21 on (e.g. 87-85 for a 113-119 game on 2023-01-12), while `game_scores` sums to Basketball-Reference's season totals exactly.
- March Madness Model data quirks, all handled in code and disclosed on the page: CollegeBasketballData.com is missing two 2017 First Four games (the Tuesday pair), so those winners enter at the Round of 64 and the losers aren't listed (66 teams); 2021's Oregon-VCU no-contest is stored as a 1-0 "scheduled" game, kept in the bracket but excluded from training and scoring; LIU's 2017-18 season is split across two names ("LIU Brooklyn", "Long Island University"), merged by one alias after checking every tournament team for a low pre-tournament game count; VCU 2021 (no NCAA game played) takes its Elo from its last pre-tournament game. The API's `endDateRange` is exclusive (checked live), which the fetcher's month windows account for.
- **stats.nba.com has been unreachable from this machine since 2026-09-26** (every endpoint times out), so `draft_history` is built from Basketball-Reference (`load_draft_history_bref.py`). NBA ids come from `player_id_map` (built by `scripts/bref_nba_ids.py`, see the player-id entry below). 3,642 of 3,747 drafted players who played are matched; 105 aren't: they keep a placeholder id and have no photo, but their Win Shares still come from Basketball-Reference.
- **Pre-2010 players Basketball-Reference and NBA ids can't settle (129 of 3,354):** `player_id_map` was rebuilt 2026-09-27 with `scripts/bref_nba_ids.py` (it used to be exact names only, leaving out Ewing, Payton, Hardaway, Glen Rice, the 1991 #1 Larry Johnson and 228 others, and giving four NBA ids two players' careers). The 129 left out, 407 player-seasons, are mostly nicknames with no shared first-name form and same-name pairs the checks can't separate (the two Mike Davises, Freddie Lewises and Sam Williamses, whose single NBA id the old map had shared); they're skipped rather than guessed. ABA seasons are still out of scope.
- College → NBA Pipeline: a player's last college season is checked against CollegeBasketballData.com player stats, which start in 2013-14, so the 2013 draft class (45 players) is linked by draft year without that check. Torvik's 2013-2025 ratings are end-of-season (tournament games included); fine for describing team strength, not usable as pre-tournament inputs.
- Real height/weight/wingspan/draft-combine data now exists (`draft_combine` table, `scripts/fetch_draft_combine.py`) but only covers players who were actually invited to and measured at a real NBA Draft Combine — not every drafted player attends (e.g. Zion Williamson and Victor Wembanyama both have a real combine row but every measurement field is NULL, since they didn't complete physical testing), and undrafted/international players who skipped it entirely have no row at all. NULL is stored, never guessed, for any test a player skipped. Fit Analysis and archetypes still use statistical clustering as a stand-in for a scouted role, since combine data doesn't cover skill/role.
- No real trade-transaction-history dataset exists for a genuine "Trade Chemistry Simulator" — Lineup Chemistry is the honest, real-data substitute (see above); a true trade simulator remains blocked on data, not effort.
- No real MVP/DPOY/ROY betting-futures market exists on the odds provider used here — checked directly against the live API before building the Vegas Scanner, which is why that feature compares championship odds instead.
- The odds API free tier is quota-limited (~500 req/month); the scanner caches live odds for 6 hours rather than fetching on every page load.
- The WPA model is trained on 7,232 unique real games across seasons 2021-2026 (real full-season ESPN/sportsdataverse coverage; the ~420-game nba_api sample turned out to be entirely games ESPN also has, so after de-duplication every game used is an ESPN copy) — always disclosed via `sample_size_games`/`n_games_train`/`n_games_test` in the relevant API responses rather than implied to be comprehensive. 42,570 of ~3.15M real ESPN-sourced player-attributed events (1.4%) couldn't be matched to a real nba_api `person_id` by name and so carry no per-player WPA attribution — a real, disclosed gap in player-level totals only, not in the model itself (training never uses `person_id`). De-duplicating removed 22 fringe 2024-25 players (two-way/end-of-bench, 2–34 plays each) from `player_wpa_totals` entirely: their only matched plays were in the dropped nba_api copies, and their ESPN plays fall in this unmatched-name gap.
- Live `nba_api`/`stats.nba.com` calls are occasionally flaky (shot-chart data, live player search) — external network reliability, handled with retries/backoff, not a code bug.
- `/games/by-date` (`fetch_nba_games_by_date`) is built around the live scoreboard endpoint, which works fast for today's real games but still returns an empty list for an older historical date — a real, pre-existing limitation of that endpoint discovered while building Schedule Fatigue (which doesn't depend on it — Live Scores' rest tags come from the separately-computed `team_game_fatigue` table). The 45+ real seconds that limitation used to cost on every request is fixed (see below — short timeout + short cache), but the empty-list-for-old-dates behavior itself is unchanged; worth a look if historical date browsing on Live Scores becomes a priority.
- Referee Tendencies' real officials data comes from `BoxScoreSummaryV2`, which has no bulk endpoint (one real call per real game) — `scripts/fetch_referee_officials.py` is resumable and grows real coverage each time it's re-run rather than fetching every real game in one sitting, so `n_games`/season span shown in the UI reflects real coverage as of whenever it was last run, not necessarily every game in scope. Separately, nba_api's own `BoxScoreSummaryV2` is confirmed (checked directly against the live endpoint) to be missing officials for some real games on/after 2025-04-10 — those games are logged as attempted so they aren't retried forever, but contribute no officials rows, a real gap in very recent coverage specifically.
- Garbage-Time Deflator uses ESPN play-by-play only (2020-21 through 2025-26). The small nba_api play-by-play sample is excluded because all 420 of its games are the same real games already in the ESPN data (418 match on date + teams; the other 2 are neutral-site games with a NULL nba_api `home_team`, same date and final score), and the 3 real NBA Cup finals are excluded because the NBA doesn't count them in official regular-season stats. ESPN's text doesn't mark missed step-back/pull-up threes as "three point", so missed 3PA are identified by that phrase or a listed distance of 23+ ft — 99.7% accurate on real made shots, where the real score change gives the true answer (made shots use the real score change directly). Assists are matched by exact name within the same game: 92.7–95.4% matched per season, the rest carry no per-player credit.
- DAD Index describes who a defender guarded and how those shots went — not a full defensive rating (no help defense, rebounding, or scheme). Matchup pairs under 5 real partial possessions were dropped at fetch time, so DAD's possession shares are over ≥ 5-possession pairs.
- **Two age conventions in `player_season_stats` (found 2026-09-28, not changed):** 2009-10+ rows carry NBA.com's `AGE`, which counts age later in the season than Basketball-Reference (February 1); in every season about 45% of players are exactly one year older than on Basketball-Reference (e.g. 2025-26 Kawhi Leonard 35 vs 34). Pre-2010 rows come from Basketball-Reference. Each source is internally consistent, and the award and similarity models were trained on the NBA.com values, so ages were left as they are; age leaderboards spanning 2009-10 mix the two conventions by up to a year. The Breakout Detector's tooltip says so.
- **No EPM or other proprietary impact metric.** EPM is proprietary and isn't used or imitated anywhere (RAPM, since 2026-09-29, is this project's own ridge regression on the play-by-play stints, not an imitation of anyone's). Every "offensive quality" weight in the advanced-analytics features (DAD Index, Spacing Lab validation, Contract Value's WAR) comes from Basketball-Reference's published BPM/OBPM/VORP (since 2026-09-27; before that, this project's own BPM 2.0 reproduction, which ran hot). The reproduction survives only as `*_repro` columns feeding Pair Synergy's trained model.
- Scouting Report has no pick-and-roll coverage type or drive direction at all (not in any real dataset this project uses). Its closest-defender / touch-time / dribble splits (v2) cover 3PT only — 2PT bands mix layups with mid-range jumpers, so they'd mostly restate where a player shoots. At p < 0.05 about 1 in 20 tested splits clears the bar by chance; the card always shows that expected count. Play-type significance rests on an estimated per-possession SD (Synergy publishes no per-possession outcomes). "Toughest defenders" samples are small (10+ shots) and descriptive.
- Gravity is a composite proxy from tracking *splits*, not true gravity (how far defenders shade toward a player off the ball) — that needs raw defender coordinates, which aren't public. The Spacing Lab's predicted ORtg change is a real across-lineup association with a modest effect size, not a forecast for any specific lineup, and is withheld outside the range of real lineups. `lineup_stats` stores each season's 2,000 most-used lineups (the endpoint's cap), so very rare lineups aren't on file.
- **Contract Value salary data is third-party and imperfect — read before trusting a number.** The two salary CSVs are Kaggle uploads the owner downloaded (a 2000–2020 file and "NBA Player Stats and Salaries 2010-2025"), built by their uploaders from HoopsHype and Basketball-Reference, with no stated license — so they're kept local in `nba_data/salaries/` (gitignored, not redistributed); to rebuild, download them into that folder as `nba_salaries_2000_2020.csv` and `nba_player_stats_salaries_2010_2025.csv`, then run `load_salaries.py` and `build_contract_value.py` (the Contract Value smoke test skips if they were never loaded). Problems found by checking against real contracts: the 2010–2025 file's 2020-21 to 2023-24 salaries are inflation-adjusted (every player scaled by the same factor per season, e.g. ×1.156 for 2021-22), so those seasons are excluded rather than reconstructed; the 2000–2020 file's 2000–2005 payrolls are incomplete (excluded), it repeats stale rows for retired players (e.g. Cuttino Mobley at $9.5M through 2012-13 — why only players who actually played are priced, making cost per win the price of on-court production rather than total spending, with dead money and injured players left out), its 2017-18 is missing major players (excluded by the 90% minutes-coverage gate), and some individual rows are wrong (both files list Stephen Curry 2017-18 at his 2018-19 salary). Scraping the sources directly isn't possible: Basketball-Reference sits behind a Cloudflare bot challenge and its terms forbid automated collection, and HoopsHype's robots.txt blocks AI agents by name. WAR depends on this project's VORP reproduction (rescaled to real wins, not replaced by Basketball-Reference's numbers). No minimum-contract label is inferred (the full years-of-service scale isn't sourced for every season).
- `player_shots` includes real playoff (`game_id` `004…`) and play-in (`005…`) shots alongside the regular season (`002…`); anything computing regular-season shooting from it must filter on `game_id`. Separately, every bulk-loaded row has a NULL `shot_zone_basic`, so zones always come from `shots_lib.classify_zone()`'s coordinate rule — corrected 2026-09-26 (see Just shipped).
- **Shot-making has no defender or shot-type context.** No shot in `player_shots` carries a closest-defender distance or a shot type (catch-and-shoot vs. pull-up), so "shot-making" (actual minus expected eFG%) also includes the defence a player faced and the shots he created for himself; a rim-runner's finishing counts the same as a shooter's jumper. Before 2010-11 about a quarter of shots (nearly all at the rim) have no exact location and sit at (0, 0), and about 7% of threes in every season carry `shot_distance = 0`, so the model uses coordinates only and treats the (0, 0) rows season by season.
- **`player_game_lines` is rebuilt from ESPN play-by-play text, not box scores.** Players with no row in `player_season_stats` (fringe call-ups such as Mamadi Diakite or Kenneth Lofton Jr. in some seasons) can't be given an NBA id, so they have no line of their own (everyone else's minutes are unaffected). A missed shot is a two or a three as the NBA shot chart calls the same shot where the two feeds match (~99% of attempts), else as the text does ("three point", or 23+ ft); season totals are within 0.25% of NBA.com's, three-point attempts included (0.9996-1.0005 a season since 2026-09-29; the text alone left them 0.6-1.9% short). Rebound % chances exclude team rebounds, so they run about 13% below NBA.com's denominator (the Stat Stability page converts).
- **Per-game on-court plus-minus from `player_game_lines` isn't reliable, so the Game Log doesn't show it** (checked 2026-09-28). In 9,194 of 12,961 team-games (71%) whose player minutes add up to a full game, the team's summed on-court margin (`tm_pts - op_pts`) is exactly 5x the final margin; in the rest it's off by multiples of 5, i.e. some stretches have the wrong number of players on the floor even though total minutes are right. Box-score lines themselves are unaffected (season totals above). The Game Log and Game Finder also can't show games a player sat out (no row), and a game where a player's name couldn't be matched is missing from his log: the profile warns when the play-by-play has fewer games than NBA.com lists for that season.
- **`lineup_stats` is capped at each season's 2,000 most-used lineups** (stats.nba.com's `LeagueDashLineups` limit when `scripts/fetch_spacing_data.py` stored them), 31–89% of a team's regulation minutes. Since 2026-09-28 it is used only for seasons before 2020-21 (Pair Chemistry, Lineup Chemistry and the team page say so per season); from 2020-21 every stint comes from play-by-play (`lineup_stints`), with its own disclosed gaps below.
- **One `player_game_lines` row has team `'NaN'` (found 2026-09-29, not changed):** Miye Oni, 2021-11-20 (`espn_401360071`), 195 seconds, no stats — the parser found no team for him in that game. Harmless for season totals; `build_assist_network.py` skips it. Fixing it is part of the same `player_game_lines` rebuild as the items below.
- **`lineup_stints`' per-side 3PA still use ESPN's text call on misses (2026-09-29):** `player_game_lines` and the Play Finder take the NBA shot chart's two-or-three call (`Game(..., miss_threes=)`), the stints don't (their `home_fg3a`/`away_fg3a` are shown nowhere, and points, possessions and everything built on them don't depend on it). If a lineup three-point stat is ever shown, rebuild the stints with `miss_three_calls()` passed in first (then rerun RAPM, rotations and rim deterrence).
- **The Game Log overcounts minutes in 9 player-games (found 2026-09-29, not changed):** in 9 ESPN games (2020-21 to 2023-24) one substitution is logged with no team ("Luka Doncic enters the game for "); the player-lines replay (`Game.run()` in `scripts/pbp_lineups.py`) then opens a phantom lineup for "no team" and counts that player's minutes on both, e.g. Dončić 45.4 minutes on 2022-01-30 instead of 37.1. The stints (`Game.stints()`) only track the two real teams and are right, so the Rotations chart shows the right minutes there and differs from the Game Log in exactly these 9 player-games (+9 s to +503 s; the smoke test pins them). Fixing it changes `player_game_lines` and its chain (the same rebuild as the id fallback below), so it waits for the owner's OK.
- **Players ESPN gives no id to are invisible to the lineup parser (found 2026-09-28, not changed):** 8–9.5k events a season (100–155 names, two-way and 10-day players such as Mamadi Diakite, Kenneth Lofton Jr., Braxton Key) carry a name but no `person_id`, and `scripts/pbp_lineups.py` resolves names only through `player_season_stats`, where these players have no row. They get no `player_game_lines` row, and every stint they were on the floor for has four identified players and is left out of `lineup_seasons` / `pair_seasons`: 6.3% of minutes in 2020-21, 6.0% in 2021-22, 2.5%, 3.8%, 2.0%, and 0.001% in 2025-26 (ESPN now ids almost everyone). `player_bio` / `player_id_map` have their NBA ids, so a fallback there would fix it, but it changes `player_game_lines` and the chain built on it (`build_player_on_off.py`, `build_stat_stability.py`, `build_hot_streak_persistence.py`, `build_situational_splits.py`, `build_projections.py`), so it is a deliberate separate rebuild, not a quiet fix.
- **`player_game_lines`' on-court points (`tm_pts`/`op_pts`) double-count in games with a stale ESPN score field:** they credit positive score changes, which reconcile with the real final in only 512 of 1,080 games in 2020-21, 505 of 1,230 in 2021-22 and 547 of 1,230 in 2022-23 (nearly all from 2023-24 on). This is the cause of the known "on-court +/- doesn't add to 5× the margin in 29% of team-games" gap. `lineup_stints` credits points from the made shots and free throws themselves (running-maximum score as fallback) and reconciles 7,220 of 7,232 games; the lines were left as they are so nothing built on them changed. In 9 player-games a substitution ESPN tagged to no team makes the lines credit a player's seconds twice; the stints credit them once.
