# NBA Hub

A full-stack NBA analytics platform built as a final-year project: real historical data (1950 through the current season for career/season stats; 2009-10 through the current season for the deepest advanced-stat coverage), trained and backtested prediction models, era-normalized player comparison engines, a live betting-market cross-reference, real play-by-play win-probability modeling, and a suite of stat-driven daily games — all built on top of one PostgreSQL database (plus an optional read-only cloud mirror — Layerbase, full parity including shot charts/play-by-play — for remote/cloud sessions) and served through three FastAPI microservices to a React dashboard.

The project's guiding rule, followed throughout: **never fabricate data**. Where a real number exists, it's used and its source is traceable to a real endpoint or a real database column. Where the project doesn't have real data for something (player height/wingspan, a trade-history dataset, a real referee-bias claim), that gap is disclosed in the UI rather than invented — several features explicitly say what they *aren't*, and small real samples get an explicit warning instead of being presented as comprehensive.

## For an AI assistant picking this project up

Read this whole section before touching anything. It exists so you don't need the owner to re-explain context that's already been established over many previous sessions.

**Environment gotchas — get these wrong and everything else breaks:**
- Plain `python3` on this machine resolves to an Anaconda install missing this project's dependencies. Always use `/Library/Frameworks/Python.framework/Versions/3.14/bin/python3` explicitly, for every script run and every `pip install`.
- Each of the three API files has its own `if __name__ == "__main__"` uvicorn fallback port, but **always pass `--port` explicitly anyway** — don't rely on the fallback, and don't assume the fallback is correct (it has been wrong before and gets fixed reactively; the ports the frontend actually calls are the ones in `frontend/src/services/api.js` — currently 8000/mvp, 8001/similarity, 8002/impact).
- DB credentials live in `api/.env` (gitignored) as `DB_HOST`/`DB_PORT`/`DB_USER`/`DB_PASSWORD`/`DB_NAME`, read through `api/db_config.py` and `scripts/db_config.py` (two separate small modules, each resolving `api/.env` by an absolute path so they work regardless of current working directory). Every script and service does `from db_config import DB_CONFIG`. **Never hardcode the password back into a file** — it used to be hardcoded everywhere and was deliberately pulled out; the old password is still in git history from before that cleanup, so treat it as not-really-secret and don't reuse it for anything real.
- Postgres DB name: `nba_analytics`.
- `DB_TARGET` in `api/.env` picks local (default, always use for dev), `layerbase` (a full-parity Postgres mirror — every table including `player_shots`/`pbp_events`, see the Layerbase entry near the bottom of the Roadmap section), or `cloud` (the older Supabase read mirror, missing `player_shots`/`pbp_events` due to its 500MB free-tier cap — kept for now, but Layerbase is the one with full parity). If you ever need to refresh a cloud copy after local data changes meaningfully: `cd scripts && python3 migrate_to_layerbase.py` (full drop-and-reload per table, chunked streaming for the two big tables, recreates non-PK indexes too) or `python3 migrate_to_supabase.py` for the Supabase copy (no `pg_dump`/`psql` needed or available on this machine, either way).
- Scripts are normally run as `cd scripts && python3 whatever.py` (their docstrings say so), but don't assume — check the top of the script; some things (like the test suite) are written to work from any cwd.
- `nba_api` hits the real stats.nba.com over the network. It's rate-limit-sensitive: existing fetch scripts use `time.sleep()` between calls (0.4–1.0s for reliable endpoints like `PlayByPlayV3`/`LeagueGameFinder`, more conservative 5–30s backoff for the flakier `shotchartdetail` endpoint) plus retry-with-backoff. Match the existing pattern in whichever script is closest to what you're building; don't invent a new rate-limiting scheme.
- Season encoding: `player_season_stats.season` and most other tables use the **end year as an int** (e.g. `2026` means the 2025-26 season). Convert to the NBA's own label format with `f"{season - 1}-{str(season)[-2:]}"` when calling `nba_api` — this exact expression appears throughout the codebase, copy it rather than reinventing it. `pbp_games`/`pbp_events` now span real seasons 2021-2026 (previously just one sampled season, see C8 below) and agree with `player_season_stats`'s latest season — but still query each table's own `MAX(season)` rather than assuming any two tables agree on "the latest season" (this exact bug was found and fixed once already in `/games/wp-replay/list`, back when they didn't).

**The "never fabricate data" rule in practice — how to apply it to new work:**
- A composite/index metric (Heliocentricity Index, Impact Score) is fine as a simple, fully-disclosed equal-weighted average of real percentile ranks. It is never presented as a trained/validated model unless it actually is one.
- A predictive/simulated feature (e.g. "what would this trade do to team chemistry") needs either a real trained model with real validation metrics, or it gets scoped down to something that only uses real data that actually happened (see Lineup Chemistry below — the honest substitute for a "Trade Chemistry Simulator" that would have needed an invented usage-redistribution formula).
- Every "what if" / counterfactual feature (see Game Replay) must say in its own API response and its own UI copy that it's a counterfactual, not a prediction of what actually would have happened.
- Small real samples get a disclosed warning/cutoff (e.g. Playoff Drop-off Forecaster's `small_sample_warning` under 10 games, Lineup Chemistry's `min_minutes` cutoff with `lineups_qualified`/`lineups_total` both returned) rather than being silently included or silently hidden.
- If a feature needs data the project doesn't have (a real API key, a real dataset), say so to the owner directly and ask, rather than fabricating placeholder data or silently declining. Registering third-party accounts / submitting signup forms with the owner's info is an action that needs the owner's explicit go-ahead, not something to do autonomously.

**Verification discipline expected on every feature before it's considered done:**
1. Test the actual data source (nba_api endpoint, SQL query, whatever) directly with real inputs *before* writing application code around it — this has caught real bugs early several times (empty-string score fields that needed forward-filling, a `CalibratedClassifierCV` API quirk, non-unique `action_number` values).
2. Run the backend, `curl` the new endpoint(s), confirm real data and the expected JSON shape.
3. Start the frontend dev server, actually click through the new UI in the browser pane (`preview_start` with name `nba-frontend`), check the browser console for errors, screenshot if it's visual.
4. Run the smoke tests: `/Library/Frameworks/Python.framework/Versions/3.14/bin/python3 -m pytest api/tests` (works from repo root or `api/`). Add a test for any new endpoint.
5. Do a real "sniff test": does a leaderboard/ranking match genuine basketball knowledge? (e.g. DeMar DeRozan's real reputation as a clutch scorer landing near the top of the Clutch WPA leaderboard was treated as evidence the whole WPA pipeline was working.)
6. `git status --short` and a `grep` for any literal secret values across changed files, every time, before staging — `api/.env` must never get committed (it's gitignored; verify with `git check-ignore -v api/.env` if in doubt).

**Commit style:** one commit per feature, detailed message explaining what's real about it and what was verified, ending with `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>` (or whichever model actually did the work — check the current session's own attribution instructions rather than assuming). Only commit when the owner asks; `git status` and read the diff before staging.

## What's in it

**Core stats & browsing**
- **Shareable links** (`frontend/src/utils/useUrlState.js`) — the open page is in the URL (`?page=builder`), so a reload, a bookmark or a pasted link opens the same page, and Back/Forward move between pages. Seven tools also keep their inputs in the link and have a **Copy link** button: Leaderboard Builder (`stat`, `from`, `to`, `gp`, `mpg`, `att`, `team`, `order`, `n`), its Build-your-own-metric mode (`mode=metric&w=pts:1,ts_pct:2` plus the same filters), Regression Explorer (`x`, `y`, seasons, floors, `within=0`), Breakout Detector (`season`, `dir`, `stats`, floors, `n`), Player Comparison (`season`, `a`, `b`), Shot Charts (`player`, `season`, `view=heatmap`) and Trade Analyzer (`season`, `ta`/`pa`, `tb`/`pb`; a full trade runs by itself on open). Changing an input rewrites the link without adding history entries; a value that's missing or no longer valid falls back to the default. Analytics tabs keep their `#hash`.
- Live scores, standings, full player-stats browser with sortable/filterable tables
- **Stat Line Finder** (Players menu, `?page=statline`, `GET /similarity/stat-line?line=pts:25,ts_pct:0.6,ast:8&season=` on the similarity service, options at `/similarity/stat-line/options`) — type a stat line (any of 16 stats, up to 10: per-game box score, 3P%/FT%/TS%, usage, assist %, rebound %, net rating, minutes, age) and get the closest real player-seasons. Same idea as Season Similarity's matrix (each stat z-scored within its own season over every player-season that has it), but the typed line is read as a standing in a season the user picks, and matches are ranked by the root-mean-square gap in z-scores on the typed stats only (levels, not cosine shape). Shooting percentages use the Leaderboard Builder's attempts floors; each stat is usable from its first well-recorded season (same catalogue; a smoke test checks they agree). The page echoes the line (season average, standing, n), shows every match's values with its gap per stat and what drives the distance, greys seasons under 40 games, warns when nothing is within one standard deviation, has example lines, a season range, games floor and one-per-player toggle, and a shareable link (`line`, `season`, `from`, `to`, `gp`, `one`, `n`). Sniff tests: Curry 2015-16's, LeBron 2012-13's and Wilt 1961-62's own lines return those seasons at distance 0; 3 blocks + 12 rebounds today gives Olajuwon, Camby, Mutombo, Wembanyama, Robinson.
- **Breakout Detector** (Players menu, `GET /explore/breakouts?season=&direction=up|down&stats=`) — the biggest season-over-season rises or drops in a player's standing within the league: each chosen stat (default points, TS%, usage, assist %, rebound %, BPM; up to 8) is z-scored within its season among players with 30+ games and 15+ minutes, and the score is the average change in standing from the season before (both seasons must qualify). Every row shows each stat before → after with its change in standing. A historical line measures regression to the mean with the same stats and filters: the 20 biggest breakouts of each season 1978-79 to 2024-25 kept a median 73% of their jump the next year (847 players; 59% for three-point stats alone). Sniff test: 2016-17 breakouts include Giannis (that year's Most Improved Player), Jokić and James Johnson; declines are led by Chandler Parsons and Curry after his unanimous MVP season.
- **Regression Explorer** (Players menu, `api/routers/explore.py`, `GET /explore/regression?x=&y=`) — pick any two of the builder's stats and a season range: a scatter of player-seasons (a fixed sample of up to 2,500 drawn; the fit uses all), the fitted line, a plain-language verdict (strength, change per standard deviation with a 95% interval, r, R²) and the 8 player-seasons furthest above and below the line. By default both stats are compared within each season (season fixed effects) so league-wide trends don't count; standard errors are clustered by player (`scripts/stats_lib.wls_cluster`). Presets include usage vs. true shooting (2015-16 to 2025-26: essentially no relationship, r = 0.01) and assists vs. turnovers (r = 0.80). The page says it's an association and names the selection effect (older players in the pool are the ones good enough to stay).
- **Leaderboard Builder** (Players menu, `api/routers/leaderboard.py`: `GET /leaderboard/options`, `GET /leaderboard/custom`) — rank single player-seasons 1949-50 to today by any of 31 stats (per game, shooting, rates, impact), with a season range, minimum games, minutes and (for shooting %) attempts per game, team, order and size, plus presets; every row shows games, minutes, points, rebounds, assists and TS% for context, and exports to CSV/JSON. Each stat starts in the first season it's recorded for at least 90% of player-seasons (steals and blocks 1973-74, threes 1979-80, net rating/plus-minus/impact 2009-10); longer ranges are trimmed with a note. Shooting percentages default to 5 FGA / 2 3PA / 2 FTA a game. Traded players show under their last team from 2009-10 on and as 2TM/3TM before. A second mode, **Build your own metric** (`GET /leaderboard/composite?weights=pts:1,ts_pct:2`), ranks player-seasons by a weighted sum of up to 8 stats (weights −3 to +3 in the UI, −5 to +5 in the API): each stat is z-scored within its own season among players passing the games/minutes filters, lower-is-better stats are flipped, shooting percentages on too few attempts count as average, and every row shows each stat's value and z-score; five presets. Caveat shown on the page: in seasons where few players did something (threes in the early 1980s) the few who did can sit 5-8 SDs above the rest.
- **News** — real headlines from 6 public RSS feeds (ESPN, NBA.com, Google News, Yahoo Sports, CBS Sports, Sports Illustrated), with a team filter (adds a real team-scoped Google News feed), keyword search, and real keyword-based category tagging (Injuries/Trade Rumors/Game Recap/Player Watch) disclosed as a heuristic on the real article text, not a source-provided category — these feeds carry no category field at all
- **Team Comparison** — real per-game stat bars (existing), plus real advanced stats (Off/Def/Net Rating, turnovers), a real head-to-head record + recent-meetings list (`team_game_fatigue`), each team's real last-10-games form, and each team's real top-8 roster by points (`api/routers/team_comparison.py`)
- Shot charts (real shot-location data, live-fetched and cached per player/season), plus **Shot mix over a career** below the chart (`common/ShotMixHistory.jsx`, `GET /shots/player/{name}/zone-history`): each regular season's share of shots in the five zones as a 100% stacked column, with a dashed line where the league's own 3-point share starts that season (`league_zone_mix`), a per-season detail table (share and FG% vs. league) and an all-seasons table with export. Seasons under 200 tracked attempts are faded; careers that began before 1996-97 say how many seasons are missing. Reusable on any page: `<ShotMixHistory key={name} playerName={name} />`.
- **Greats of the Game** (`scripts/build_greats.py` → `greats`, `GET /greats`, Players menu) — the NBA 75th Anniversary Team (76) plus today's stars by a stated rule (played in 2025-26, not on the 75th team, 3+ All-NBA selections with one in the last three All-NBA seasons: Jokić, Dončić, Embiid, Tatum, Butler, Gilgeous-Alexander, Towns). Full-bleed hero: five rows of NBA headshots drifting sideways in an orange halftone treatment, faces colouring in near the cursor (a slow spotlight sweep on touch screens; still under reduced motion), a ticker of headline facts, then filter/sort and a card per player with a detail panel. Numbers are Basketball-Reference NBA/BAA regular-season totals (ABA seasons not counted; no championship data exists, so rings are never shown): MVPs, All-NBA (1st team), All-Defense, All-Star, Naismith Hall of Fame, Win Shares and best season. Facts are generated from the data (all-time ranks, times leading the league in season totals, top-3 MVP finishes, best season, draft pick, college, debut age; pick numbers omitted before 1966, the territorial-pick era). "Did you know?" trivia for 34 players (67 items) is either proven by league-wide records in the data (e.g. Curry's all-time and single-season three-point records and the only unanimous MVP) or a well-known fact checked against a linked Wikipedia article (e.g. Curry "credited with revolutionizing the game", Wilt's 100-point game); the check caught one stale claim (Kobe's 81 is no longer the second-highest game — Bam Adebayo scored 83 in 2026). Photos: 260x190 CDN images on the wall (~16 KB each), 1040x760 only in the detail panel; the CDN's blank silhouette (Kidd, Wilkens, Ewing) is detected by hash and replaced with an initials tile.
- Stat leaders, Draft Value Guide (Basketball-Reference Win Shares in each pick's first five NBA seasons, draft classes 1980-2021, plus every draft class 1947-2025 with career Win Shares and All-Star selections), Rookie Class Tracker (this season's rookies ranked by real ROY probability). Stat Leaders also includes a real **Hustle** stat group (deflections, contested shots, screen assists, loose balls, charges drawn, box outs — NBA's own real hustle-stat tracking, `scripts/fetch_hustle_stats.py`) alongside the traditional box-score stats.
- **Hall of Fame** — real all-time career leaders, single-season records, and career-longevity leaders, computed live from `player_season_stats`' full 1950-2026 coverage (`api/routers/hall_of_fame.py`). Named for "statistical greatness," not literal induction — this project has no real Naismith Hall of Fame membership dataset from any source it uses, and says so directly in the page's own `InfoTooltip` rather than implying verified induction data it doesn't have. Real, separate accolade layered on top: a gold "75" badge for the actual NBA 75th Anniversary Team (76 real players, announced 2021-10-21, `scripts/load_nba75_team.py`, `nba75_team` table) — sourced from Wikipedia and cross-checked name-for-name against `nba_api`'s own static player list.

**Player Comparison**
- Head-to-head statistical profiles with percentile ranks against a real qualified-player pool
- **Scouting Report ("Exploit Guide") v1 + v2** (`scripts/build_scouting_reports.py`, `GET /players/scouting-report/{player_name}`) — automatic, significance-filtered scouting keys for every player-season with 1,500+ real regular-season minutes (2,502 player-seasons, 2012-13 through 2025-26), shown as an "Exploit Guide" card (titled that way in the UI because Player Comparison already has an unrelated "Scouting Report" stat table) in every player's detail view and side by side on Player Comparison. Each real split is tested against a real baseline: FG% in each of 5 shot zones vs. the rest of the league in that zone (two-proportion z-test, 50+ FGA, regular-season shots only), and points per possession in each NBA Synergy play type vs. the rest of the league (z-test, 50+ possessions — Synergy publishes no per-possession outcomes, so the per-possession SD is estimated per season and play type from the real spread of player PPPs by method of moments, landing at a plausible ~0.8–1.6 points; Synergy's "Misc" catch-all isn't tested); and, from 2013-14 (v2, `scripts/fetch_shot_context.py`), 3PT FG% in each NBA closest-defender band (0-2 / 2-4 / 4-6 / 6+ ft), touch-time band (< 2 / 2-6 / 6+ s) and dribble band (0 / 1 / 2 / 3-6 / 7+) vs. the rest of the league in the same band (two-proportion z-test, 50+ attempts; 3PT only, because a first run showed 2PT bands just restating shot location — Giannis came out "strong" in every tight-defense, short-touch and 0-dribble 2PT band, i.e. his rim finishing again). Categories count as scouting keys only if their own findings persist: the lower bound of the 95% Wilson interval on the next-season same-direction rate must exceed 50% — decided by the data, not hand-picked. Only p < 0.05 findings are listed (up to 3 strengths, 3 weaknesses, strongest per category first so one skill isn't listed three ways) as template text with real numbers and n, alongside how many splits were tested and how many would clear p < 0.05 by chance. Also shows the toughest real defenders against the player (`player_matchups`, 20+ partial possessions and 10+ of his shots, with a p-value) and an explicit "what this report can't tell you" list (no pick-and-roll coverage type, no drive direction, no closest-defender distance yet, no help defense/scheme). **Real validation:** of 3,260 real findings whose player qualified again the next season, 84.3% point the same direction the following season (zones 87.0%, play types 82.8%, closest-defender 82.6%, dribbles 82.9%, touch time 83.8%; chance would be 50%). High-leverage FG% (from the Garbage-Time Deflator) is tested but deliberately *not* listed as a strength or weakness — the same check found it no better than chance (54.3% same direction, 5.7% significant again, n = 35), the well-known "clutch isn't a stable skill" result — so the reliability rule drops it to reference only. Sniff test: 2024-25 Giannis Antetokounmpo — restricted area 74.9% vs. 66.2% league (strength), spot-ups 0.75 vs. 1.06 PPP (weakness); 2025-26 Shai Gilgeous-Alexander — mid-range 55.0% vs. 41.4% league; 2024-25 Stephen Curry — 1-dribble threes 50.9% vs. 32.4% league and quick-release (< 2 s touch) threes 44.8% vs. 36.8% (strengths), threes after a 6+ s touch 25.7% vs. 33.7% (weakness).
- Any player's detail view (opened from Players, Stat Leaders, etc.) shows a real **Play-Type Profile**: real share of offensive possessions by real play type (NBA Synergy tracking, `scripts/fetch_playtypes.py`) with real points-per-possession for each, color-coded by percentile
- Fit Analysis: **Real Pair Synergy** — a real ridge regression (`scripts/train_pair_synergy.py`), trained on 23,381 real 2-man lineup pairs across all 17 real seasons and validated with real season-grouped cross-validation (real R² = 0.0148, disclosed honestly even though it's low — a real finding that pair chemistry isn't well predicted by box-score features alone, not a bug). Predicts a pair's expected real net rating above what their two individual real net ratings alone would suggest, and shows the pair's real observed net rating live-fetched from the NBA's own data when the two players have actually shared the floor. The older percentile-threshold heuristic (usage/spacing/role-overlap flags) is kept underneath as a simpler, unvalidated fallback.

*Player Analysis*
- Season Similarity & Player Archetypes — cosine-similarity and K-Means clustering, both **era-normalized**: every feature is z-scored within its own season before comparison. Season Similarity (2009-10 on, where usage and net rating exist) shows each match's full stat line next to the searched season with a plain-language reason ("closest on usage and assist %; differs most: lower true shooting"), and can be filtered to other players only, one season per player and a minimum games count (`GET /similarity/season-profile/{player}/{season}`). Player Archetypes includes a **League Evolution** panel: a real stacked-area chart of each archetype's share of the qualified pool across all 17 seasons, plus minutes-weighted real league-average trend lines for 3PA rate, True Shooting %, and a disclosed real pace proxy — cleanly reproduces the real, well-documented 3-point revolution and pace revival as a sanity check.
- **Player Roles** (Player Archetypes page, `scripts/build_player_roles.py`) — ten roles found by K-Means on what players do with their minutes rather than per-game totals: usage/assist/turnover/rebounding rates, steals and blocks per 36, free-throw rate, true shooting, and shot location shares (rim, paint, mid-range, corner three, above-the-break three, from `player_shots` via `shots_lib.classify_zone`), z-scored within each season, 5,386 player-seasons 2010-2026 (15+ mpg, 20+ games, 100+ located shots). K = 10 is the most roles whose grouping survives refitting on 80% subsamples (adjusted Rand 0.83; 11+ roles drop to 0.52-0.64); separation is low at every K (silhouette 0.10: styles are a continuum), which the page says. Names come from matching centroids to written role profiles (Hungarian assignment): Lead Creator (Harden, Dončić, SGA), Combo Guard, Mid-Range Scorer (Durant, DeRozan, Booker), Above-the-Break Shooter (Klay, Beal), Corner Spot-Up Shooter, Defensive Wing (Anunoby, 2015 Kawhi), Balanced Forward, Interior Finisher (Zion, Mobley), Rim-Running Big (DeAndre Jordan, Gobert, Jarrett Allen), Skilled Big (Embiid, Horford, AD). The older six-way archetypes (`cluster_players.py`, `player_clusters`) are unchanged because Pair Synergy's trained model and Trivia use those names; they show as each player's "family".

Real silhouette score (0.21) is disclosed as lower than the stat archetypes' — play-type mixes genuinely overlap more than production profiles do. Sits right below Player Archetypes with its own scatter plot and table.

- **Heliocentricity Index** — real touch/possession-share data (`nba_api`'s `LeagueDashPtStats`) combined with real usage%/assist% into a disclosed, equal-weighted percentile-rank composite (modeled on the Impact Score's own precedent). Explicitly not a predictive "slider" — just an honest index of who the real offense actually runs through.
- **Clutch-Time Win Probability Added (WPA) Tracker** — a real trained Logistic Regression win-probability model (same library/approach as the MVP/DPOY/ROY models), fit on real play-by-play from two real sources (`scripts/fetch_play_by_play.py` for nba_api, `scripts/fetch_pbp_espn.py` for real full-season ESPN coverage via sportsdataverse → `train_wpa_model.py` → `compute_wpa.py`), isotonic-calibrated, held out by *game* (not by row) to avoid leakage — 7,232 unique real games across seasons 2021-2026 (each real game counted once: the 420 nba_api games that ESPN also has are dropped in favor of the ESPN copy, `wpa_lib.PBP_DEDUP_WHERE`), real held-out ROC-AUC 0.830 (0.850 clutch-time-only) on 1,447 held-out games. WPA per play = the model's real win-probability output after the play minus before it, attributed to whichever player made the play, summed over the NBA's own real "clutch time" definition (final 5 min of regulation/OT, score within 5). The real sample size is always shown, not implied to be the full historical record.
- **Matchup Finder ("Kryptonite" defender finder)** — real player-vs-player defensive matchup data (`nba_api`'s `LeagueSeasonMatchups`, `scripts/fetch_matchups.py`: real partial possessions matched up, real FG% allowed, 571,608 real rows 2017-18 through 2025-26). Search any player as either the scorer (which real defenders have actually held them to the lowest FG%, and which have they torched) or the defender (which real offensive players do they actually shut down, and which torch them), reversible either direction. Disclosed sample-size guardrail: pairs under 20 real partial possessions are greyed out and marked "small sample" rather than silently ranked alongside reliable ones — a single defended shot is either 0% or 100%.
- **Garbage-Time Deflator** (`scripts/build_leverage_splits.py`, `GET /players/garbage-time`, `GET /players/garbage-time/player/{id}`) — splits every real player's real production by how much the game was on the line when it happened. Every real play in ESPN's full-season play-by-play gets a **Leverage Index**: the expected absolute win-probability swing of the next play at that game state (seconds left × score margin before the play), from the project's own deployed WPA model and the real league-wide mix of scoring outcomes, scaled so the average real play is exactly 1.0. Plays are bucketed garbage (pre-play WP > 99% either way, or 2nd half/OT with margin ≥ 18) → high (LI ≥ 1.5 or NBA clutch time) → low (LI < 0.3) → medium, first match wins (garbage is checked before clutch on purpose; ~17% of real NBA-clutch plays are already >99% decided, and that count is shown). Outputs raw / ex-garbage / filtered PPG, True Production Ratio, leverage-weighted PPG, and a "high stat-padding risk" badge only at ≥ 90th percentile garbage-time share among qualified (40+ game) players, with the percentile and n shown. UI: slope chart of the top 30 scorers, "Most empty calories" / "Most clutch-heavy" leaderboards (min-PPG filter, since deep-bench players dominate otherwise), a searchable per-player bucket card, and a methods/thresholds drawer. **Real validation:** rebuilt per-game scoring vs. the official per-game line, r = 1.000 and mean absolute error 0.025–0.031 PPG in every season 2020-21 through 2025-26 (n ≈ 325–367 qualified players each); 98.7–99.98% of real points credited to a matched player.
- **DAD Index (OBPM-weighted) — Defensive Assignment Difficulty** (`scripts/fetch_defend_dashboard.py` → `scripts/build_dad_index.py`, `GET /defense/dad`) — how hard each real defender's real assignments were: `DAD = Σ (share of the defender's real partial possessions vs. player i × OBPM of player i)` over `player_matchups`' real tracking data (2017-18 through 2025-26). OBPM is Basketball-Reference's published Offensive Box Plus/Minus (`load_bref_bpm_vorp.py`; until 2026-09-27 it was this project's own reproduction, which ran hot); EPM is proprietary and not used. Offensive players under 500 real minutes (or with no stored season line) count as replacement level, −2.0 (3.7–5.3% of real possessions per season). Qualified defenders: 1,000+ real partial possessions (317–344 per season); z-scored per season, plus a within-position (G/F/C) z-score, because qualified centers average +0.65 on the plain z (+0.95 with the old in-house OBPM), mostly because they guard other starting bigs. Plotted against the NBA's own real defended-FG% differential (`LeagueDashPtDefend`: defended FG% − the same shooters' normal FG%), with a real 95% sampling margin on every defender and anyone under 300 real defended shots faded. Quadrants (Lockdown vs. stars / Hidden / Targeted / Struggling vs. stars) split at z = 0 and a 0-point differential, and are labeled descriptive. **Real validation:** year-over-year stability r = 0.52–0.70 for the same real defenders qualified in consecutive seasons (DAD measures a persistent role, not noise); DAD vs. DFG% differential r = −0.25 to −0.38 (descriptive). Sniff test: known stoppers Lu Dort, Alex Caruso, Dillon Brooks, Jrue Holiday and Herb Jones all draw well-above-average assignments (z +0.61 to +2.16 across 2023-24 and 2025-26; Dort highest at +2.00 / +2.16), while Tyrese Haliburton (−1.75, 2024-25), Stephen Curry (−1.76, 2025-26) and Trae Young (−1.22, 2023-24) draw well-below-average ones.

*Teams & Markets*
- Vegas vs. Machine — real live championship-winner odds across multiple real sportsbooks, de-vigged with Shin's method, with per-book breakdown and a consensus-disagreement signal (coefficient of variation across books).

![Vegas Scanner](docs/screenshots/vegas_scanner.png)

- Playoff Drop-off Forecaster — real regular-season vs. real playoff advanced stats for the same player-season, with a small-sample warning under 10 real playoff games.
- **Lineup Chemistry** — real 5-man lineup combinations that have actually shared the floor this season (`nba_api`'s `LeagueDashLineups`: real Off/Def/Net Rating, minutes, AST%, TS%), Best/Worst toggle, with a disclosed minimum-shared-minutes cutoff (`lineups_qualified` of `lineups_total` always shown) since tiny real samples produce real but extremely noisy net ratings. This is the honest substitute for a "Trade Chemistry Simulator" — instead of inventing a usage-redistribution formula for a lineup that's never played together, it shows how real lineups that *have* actually played together have actually performed.
- **Gravity Index & Spacing Lab** (`scripts/fetch_spacing_data.py` → `scripts/build_gravity_index.py`, `GET /spacing/gravity`, `GET /spacing/lineup`) — a **disclosed composite proxy** for shooting gravity (not player-tracking gravity, which needs raw defender coordinates this project doesn't have), 2013-14 through 2025-26. Three real components, each z-scored within the season against 500+ minute players and summed: 3PA per 100 possessions; catch-and-shoot 3P%; and the share of 3PA taken with a defender within 6 ft (the NBA's own closest-defender bands). The last two are shrunk with a 250-attempt prior toward the real rate of players with similar 3-point volume that season — a disclosed departure from the plan's "shrink to the league mean", made because the league-mean prior rated non-shooters as average (Rudy Gobert, 0 3PA in 2024-25, landed above a fifth of real shooters; after the change he's at the 7.5th percentile and Stephen Curry at the 99.7th). Tracking data covers 98.8–99.8% of real box-score 3PA every season. Lineup spacing = the five players' summed Gravity. The Spacing Lab lets you pick any five players and shows their spacing percentile among that season's real 100+-possession lineups, a half-court drawn to real court dimensions and tinted by that percentile (labeled as a visualization of the index, not player positions), whether those five really played together (and their real ORtg), and a predicted ORtg change vs. a median-spacing lineup — only when the validation is significant **and** the lineup's spacing is within the range of real lineups that season (the five highest-Gravity players sum to ~+26, far beyond any real lineup's ~+15, so that combination gets an explicit "outside real data" message instead of an extrapolated number). **Real validation:** 4,256 real 5-man lineups with 100+ possessions: weighted least squares of real ORtg on lineup spacing + the five players' summed OBPM + season fixed effects, standard errors clustered by team-season (390 clusters; `scripts/stats_lib.py`, checked by simulation — reported SE 0.0618 vs. empirical 0.0615, 96% CI coverage). Result with Basketball-Reference's OBPM (2026-09-27): +0.074 ORtg per spacing point (95% CI 0.014–0.134, p = 0.016); R² 0.3595 vs. 0.3586 without spacing — a small effect (25th→75th percentile spacing ≈ +0.4 ORtg). With the old in-house OBPM it was +0.163 (p ≈ 2e-6): better-measured lineup quality absorbed about half of what looked like a spacing effect. Sniff test: the real 2024-25 Knicks starting five scores +5.82 (81st percentile), predicted +0.3 (95% CI +0.06 to +0.6) vs. a median lineup; their real ORtg together was 117.7 over 1,939 possessions.
- **Contract Value ("Moneyball Engine")** (`scripts/load_salaries.py` → `scripts/build_contract_value.py`, `GET /contracts/value`, `GET /contracts/player/{id}`) — real production priced in dollars vs. real salary, for 2005-06 through 2016-17, 2018-19, 2019-20 and 2024-25. Fair value = max(WAR, 0) × that season's real cost per win + the real league minimum; surplus = fair value − real salary. **Cost per win** = (real salaries of the players who actually played − players × the real 0-years league minimum) ÷ (real league wins − what .200 teams would win), from real salaries, real team records (`Team Summaries.csv`) and the real CBA minimum salary (sourced per season from Larry Coon's CBA FAQ and Hoops Rumors, stored with its source in `league_minimum_salary`) — $2.08M/win in 2005-06 up to $6.11M in 2024-25, never assumed. **WAR** = VORP × 2.7 (Basketball-Reference's conversion) on Basketball-Reference's published VORP, then rescaled per season so positive WAR sums to the real wins above replacement (raw positive WAR sums to 1.25–1.31× them; scale factor 0.77–0.80, shown in the UI). With the old in-house VORP that ratio was 1.27–2.00× and priced 2024-25 SGA at a $279M "fair value", which is how the reproduction's problem was first spotted. Only players who actually played are priced (see Known real gaps for why). UI (Teams & Markets → Contract Value): the season's cost per win with its full real calculation, a salary-vs-WAR scatter with the fair-value line, Top 10 bargains (500+ minutes), Top 10 cap liabilities (paid $25M+), and a methods drawer; the Trade Analyzer also shows both traded players' real salary, WAR, fair value and surplus when the season has salary data. "Rookie-scale years" is labeled only from real draft data (first-round pick, seasons 1–4). **Checks:** salaries matched to real players for 96.8–100% of each included season's real minutes (seasons under 90% are excluded — 2017-18, at 88.2%, is missing LeBron, Durant and others in the source file). Sniff test: the biggest bargain of 2015-16 is Stephen Curry (unanimous MVP on $11.4M, +$45.1M surplus); 2019-20's top bargains after Giannis Antetokounmpo are rookie deals (Luka Dončić, Jayson Tatum, Pascal Siakam, Bam Adebayo); 2024-25's worst liabilities are Bradley Beal, Joel Embiid and Paul George.
- **Game Win-Probability Replay** — replays one real game's entire real play-by-play through the same real WPA model, charting home win probability over the whole game (top 5 real plays by |WPA| marked, hover for details), plus a clickable "what if this real missed shot had gone in" counterfactual (dashed line) that recomputes the rest of the game's win probability assuming the shot's points landed and every later real play happened exactly as it did — clearly labeled as a counterfactual, not a re-simulation.
- **With vs. Without a Star** — pick a real team, season, and player: real record, win%, and average point differential split by whether that real player actually played in each real game that season, live-fetched from the NBA's own full-season game logs. Labeled explicitly as a real association, not a causal claim (other absences in the same games aren't controlled for) — a real sniff test on the 2023-24 Sixers/Embiid split (79.5% win rate with him vs. 37.2% without, across 39 and 43 real games) reproduces that season's well-documented real storyline exactly.
- **Schedule Fatigue** — real rest days, real back-to-backs, real travel miles (haversine between each real consecutive game's real arena location, `scripts/arenas.py`), and real time zones crossed for every real team-game 2010-2026 (`scripts/build_schedule_fatigue.py`, 40,696 real rows). A real win%-by-rest-bucket study (44.4% on 0 real rest days vs. 51-53% on 1-3, a clean real reproduction of the NBA's well-documented back-to-back fatigue effect) and a real team schedule-difficulty ranking by total real travel miles. Live Scores also gets real "B2B" / rest-disadvantage tags per team, computed from this same real stored schedule.
- **Referee Tendencies** — real officials (`BoxScoreSummaryV2`) matched to the real fouls/FTA/pace each of their real games produced (`LeagueGameFinder`), season-adjusted against the real league average for those same real seasons, with a real 95% confidence interval on the difference (`scripts/fetch_referee_officials.py`, `scripts/build_referee_tendencies.py`). Deliberately descriptive, not diagnostic: it compares real games-called totals to a real baseline and says nothing about cause — crew assignment, opponent style, and era are real, unmeasured confounders — and officials under 25 real games worked are explicitly flagged as a small sample rather than ranked alongside officials with a real full season on file. `fetch_referee_officials.py` is a real one-call-per-game pipeline (nba_api has no bulk officials endpoint) — resumable and safe to re-run; it skips every game_id it has already attempted, so real coverage grows each time it's run rather than needing to finish in one sitting.

*College & Draft*
- Draft Prospect Comp Finder — ~105,000 real D1 college player-seasons (CollegeBasketballData.com), era-normalized, matched by name to real NBA rookie outcomes wherever a real match exists (~55% of NBA rookies since 2015 — international/G-League/draft-and-stash players never appear in US college data). Optional "include measurements" toggle adds real wingspan-minus-height and real standing reach (NBA Draft Combine, `scripts/fetch_draft_combine.py`, 1133 real player-measurements 2010-2026) to the comp vector, narrowing to real combine attendees only. A **"Does Length Matter?"** card real-correlates wingspan-minus-height against real career-average DBPM and real steals+blocks per 36 (n=565, Pearson r shown, scatter plot) — a real, weak-to-moderate positive correlation, not a causal claim. Real body measurements also show in the Player Comparison profile when a player has them on file.
- **College → NBA Pipeline** — every NBA pick 2013-2025 who came from a US college (613 of 615; one junior-college pick and Shaedon Sharpe, who never played a college game, are left out), linked to that college team's season in Bart Torvik's ratings (national rank, opponent-adjusted efficiency margin, NCAA tournament run), and to Basketball-Reference Win Shares in the first four NBA seasons against a draft-slot expectation (`WS4 = 17.42 − 3.78 × ln(pick)`, fitted on all 598 picks 2013-2022). Only classes through 2022 (478 college players) have four NBA seasons and get a verdict. **Finding: once you know the pick, college team strength barely matters** — +0.38 WS per +10 points of team margin, 95% bootstrap range −0.30 to +1.04, r = 0.05; every team-rank tier and tournament-run group's interval crosses zero. Picks with no US college come in at −1.41 WS vs. slot (−2.44 to −0.25), mostly the draft-and-stash effect (31% played no NBA games in four seasons vs. 5% of college picks). Also a school table (≥5 picks, with ranges) and a searchable player table with headshots. `scripts/load_college_teams.py` → `scripts/build_college_pipeline.py`, `GET /college/pipeline`, Analytics tab `#pipeline`.
- **March Madness Model** — pre-tournament odds for every NCAA bracket 2013-2026 (no 2020 tournament), from inputs known before the first tip: an opponent- and venue-adjusted scoring margin fitted here (ridge least squares on every D1-vs-D1 game before the tournament, margins capped at ±25), CollegeBasketballData.com Elo going into the tournament, and seed. Logistic regression on the difference between two teams, then 20,000 simulations of the real bracket. Five input sets were compared by leave-one-season-out backtest on 2013-2025 (801 tournament games) and the best held-out log loss was kept: **adjusted margin alone** (log loss 0.557, 70.4% of games called; seeds alone 0.581 / 69.4%; margin+Elo 0.557 / 70.8%; Elo alone 0.597 / 66.8%). Honest result: better-calibrated than seeds game by game (round-by-round log loss 0.216 vs 0.229), but **not better at finding the champion** — the champion was the model's favourite in 2 of 12 backtest seasons and in its top 4 in 7, while it was a 1 seed in 9. **2026 was held back entirely as the final test:** Michigan won; the model had them 3rd (18.9%) before tip-off; it called 71.6% of games vs 72.4% for seeds (same-seed games count as half for seeds), with log loss 0.473 vs 0.517. Torvik's end-of-season ratings are deliberately not used (they include the tournament). `scripts/fetch_cbb_games.py` → `scripts/build_ncaa_model.py`, `GET /college/madness?season=`, Analytics tab `#madness`.

## Established conventions & patterns (follow these, don't reinvent)

- **Era-normalization**: any feature comparing players across seasons z-scores each stat within its own season's qualified pool first (`cluster_players.py`, the similarity engines, the Draft Prospect bridge pool). Never pool raw stat values across eras.
- **Headshots/logos**: `<PlayerHeadshot playerId={} playerName={} size={} />` and `<TeamLogo abbreviation={} size={} />` (both in `components/common/`) — they fail gracefully to initials/a fallback, never a broken image icon.
- **Tooltips**: `<InfoTooltip label="..." title="...">` for any "how does this work" disclosure — the project's standard place to put honest methodology explanations rather than burying them in a modal or leaving them unexplained.
- **Source badges**: every main Analytics endpoint's JSON includes a `_source` object (`api/source_badge.py`'s `make_source(tables, upstream_api, as_of=None, live=False)`) disclosing which real Postgres table(s) backed the response, which real upstream API/dataset those tables came from, and — for the handful of endpoints that live-fetch rather than read a precomputed table — that it's live. The frontend renders it with `<SourceBadge source={data?._source} />` (`components/common/SourceBadge.jsx`) next to the section's `InfoTooltip`; it renders nothing if `_source` is absent, so it's safe to add to a new endpoint at any time without touching the frontend contract.
- **Page links**: pages are listed in `PAGES` in `frontend/src/App.jsx` (ids match `navConfig.js`) and live in `?page=<id>`. Navigate with the `onNavigate(page, hash)` prop App passes to every page (TopNav, CommandPalette, Landing and Methodology use the same function); it pushes a history entry. Never set `window.location.hash` after navigating: pass the Analytics tab as `hash` instead.
- **Tool inputs in the link**: read them once when the component sets up its state (`useInitialParams()` + `parseParam.int/num/oneOf/str/list`, each returning null for a missing or bad value so you fall back to the default) and mirror them back with `useUrlSync({ key: value })` (null/''/[] removes a key; pass null while options are still loading). Keep keys short and readable, and add `<CopyLinkButton />` (`components/common/`) to the tool's title row.
- **Analytics tabs**: registered in `TAB_GROUPS` in `frontend/src/components/pages/AnalyticsSection.jsx`, grouped into Models / Player Analysis / Teams & Markets / Prospects. The active tab syncs to `location.hash` via `history.replaceState` (no back-button spam) so any tab is directly linkable, e.g. `http://localhost:5173/#wpa`.
- **Table export**: put `<TableExport />` directly before any new data table (or its `.table-wrapper`); `DataTable` already has it. It reads the rendered table, so there's nothing to wire to the data. Mark decoration inside cells with `data-export-skip`, or give a badge plain words with `data-export-as="..."`. Pass `name="..."` when the nearest heading above the table isn't its title.
- **Live external fetches** in the API layer are cached in an in-process `_CACHE` dict with a TTL (see `impact_api.py`'s `_CACHE`/`_CACHE_TTL_SECONDS`) rather than hitting `nba_api`/external APIs on every request.
- **New feature checklist**: pipeline script in `scripts/` (if new data needed) → Postgres table → endpoint in the right API file (awards/validation → `mvp_api.py`; similarity/clustering → `similarity_api.py`; everything else → a new or existing file under `api/routers/`, sharing helpers from `api/impact_core.py`), with a `_source` object on the response → `fetchXyz()` function in `services/api.js` → `XyzSection.jsx` component with a `<SourceBadge>` → registered in `AnalyticsSection.jsx`'s `TAB_GROUPS` → smoke test → verified in browser → committed.

## Known real gaps (disclosed, not hidden)

- March Madness Model data quirks, all handled in code and disclosed on the page: CollegeBasketballData.com is missing two 2017 First Four games (the Tuesday pair), so those winners enter at the Round of 64 and the losers aren't listed (66 teams); 2021's Oregon-VCU no-contest is stored as a 1-0 "scheduled" game, kept in the bracket but excluded from training and scoring; LIU's 2017-18 season is split across two names ("LIU Brooklyn", "Long Island University"), merged by one alias after checking every tournament team for a low pre-tournament game count; VCU 2021 (no NCAA game played) takes its Elo from its last pre-tournament game. The API's `endDateRange` is exclusive (checked live), which the fetcher's month windows account for.
- **stats.nba.com has been unreachable from this machine since 2026-09-26** (every endpoint times out), so `draft_history` is built from Basketball-Reference (`load_draft_history_bref.py`). NBA ids come from `player_id_map` (built by `scripts/bref_nba_ids.py`, see the player-id entry below). 3,642 of 3,747 drafted players who played are matched; 105 aren't: they keep a placeholder id and have no photo, but their Win Shares still come from Basketball-Reference.
- **Pre-2010 players Basketball-Reference and NBA ids can't settle (129 of 3,354):** `player_id_map` was rebuilt 2026-09-27 with `scripts/bref_nba_ids.py` (it used to be exact names only, leaving out Ewing, Payton, Hardaway, Glen Rice, the 1991 #1 Larry Johnson and 228 others, and giving four NBA ids two players' careers). The 129 left out, 407 player-seasons, are mostly nicknames with no shared first-name form and same-name pairs the checks can't separate (the two Mike Davises, Freddie Lewises and Sam Williamses, whose single NBA id the old map had shared); they're skipped rather than guessed. ABA seasons are still out of scope.
- College → NBA Pipeline: a player's last college season is checked against CollegeBasketballData.com player stats, which start in 2013-14, so the 2013 draft class (45 players) is linked by draft year without that check. Torvik's 2013-2025 ratings are end-of-season (tournament games included); fine for describing team strength, not usable as pre-tournament inputs.
- Real height/weight/wingspan/draft-combine data now exists (`draft_combine` table, `scripts/fetch_draft_combine.py`) but only covers players who were actually invited to and measured at a real NBA Draft Combine — not every drafted player attends (e.g. Zion Williamson and Victor Wembanyama both have a real combine row but every measurement field is NULL, since they didn't complete physical testing), and undrafted/international players who skipped it entirely have no row at all. NULL is stored, never guessed, for any test a player skipped. Fit Analysis and archetypes still use statistical clustering as a stand-in for a scouted role, since combine data doesn't cover skill/role.
- No real trade-transaction-history dataset exists for a genuine "Trade Chemistry Simulator" — Lineup Chemistry is the honest, real-data substitute (see above); a true trade simulator remains blocked on data, not effort.
- No real MVP/DPOY/ROY betting-futures market exists on the odds provider used here — checked directly against the live API before building the Vegas Scanner, which is why that feature compares championship odds instead.
- The odds API free tier is quota-limited (~500 req/month); the scanner caches live odds for 6 hours rather than fetching on every page load.
- The WPA model is trained on 7,232 unique real games across seasons 2021-2026 (real full-season ESPN/sportsdataverse coverage; the ~420-game nba_api sample turned out to be entirely games ESPN also has, so after de-duplication every game used is an ESPN copy) — always disclosed via `sample_size_games`/`n_games_train`/`n_games_test` in the relevant API responses rather than implied to be comprehensive. 42,570 of ~3.15M real ESPN-sourced player-attributed events (1.4%) couldn't be matched to a real nba_api `person_id` by name and so carry no per-player WPA attribution — a real, disclosed gap in player-level totals only, not in the model itself (training never uses `person_id`). De-duplicating removed 22 fringe 2024-25 players (two-way/end-of-bench, 2–34 plays each) from `player_wpa_totals` entirely: their only matched plays were in the dropped nba_api copies, and their ESPN plays fall in this unmatched-name gap.
- Live `nba_api`/`stats.nba.com` calls are occasionally flaky (shot-chart data, live player search) — external network reliability, handled with retries/backoff, not a code bug.
- `/games/by-date` (`fetch_nba_games_by_date`) is built around the live scoreboard endpoint, which works fast for today's real games but still returns an empty list for an older historical date — a real, pre-existing limitation of that endpoint discovered while building Schedule Fatigue (which doesn't depend on it — Live Scores' rest tags come from the separately-computed `team_game_fatigue` table). The 45+ real seconds that limitation used to cost on every request is fixed (see below — short timeout + short cache), but the empty-list-for-old-dates behavior itself is unchanged; worth a look if historical date browsing on Live Scores becomes a priority.
- Referee Tendencies' real officials data comes from `BoxScoreSummaryV2`, which has no bulk endpoint (one real call per real game) — `scripts/fetch_referee_officials.py` is resumable and grows real coverage each time it's re-run rather than fetching every real game in one sitting, so `n_games`/season span shown in the UI reflects real coverage as of whenever it was last run, not necessarily every game in scope. Separately, nba_api's own `BoxScoreSummaryV2` is confirmed (checked directly against the live endpoint) to be missing officials for some real games on/after 2025-04-10 — those games are logged as attempted so they aren't retried forever, but contribute no officials rows, a real gap in very recent coverage specifically.
- Garbage-Time Deflator uses ESPN play-by-play only (2020-21 through 2025-26). The small nba_api play-by-play sample is excluded because all 420 of its games are the same real games already in the ESPN data (418 match on date + teams; the other 2 are neutral-site games with a NULL nba_api `home_team`, same date and final score), and the 3 real NBA Cup finals are excluded because the NBA doesn't count them in official regular-season stats. ESPN's text doesn't mark missed step-back/pull-up threes as "three point", so missed 3PA are identified by that phrase or a listed distance of 23+ ft — 99.7% accurate on real made shots, where the real score change gives the true answer (made shots use the real score change directly). Assists are matched by exact name within the same game: 92.7–95.4% matched per season, the rest carry no per-player credit.
- DAD Index describes who a defender guarded and how those shots went — not a full defensive rating (no help defense, rebounding, or scheme). Matchup pairs under 5 real partial possessions were dropped at fetch time, so DAD's possession shares are over ≥ 5-possession pairs.
- **Two age conventions in `player_season_stats` (found 2026-09-28, not changed):** 2009-10+ rows carry NBA.com's `AGE`, which counts age later in the season than Basketball-Reference (February 1); in every season about 45% of players are exactly one year older than on Basketball-Reference (e.g. 2025-26 Kawhi Leonard 35 vs 34). Pre-2010 rows come from Basketball-Reference. Each source is internally consistent, and the award and similarity models were trained on the NBA.com values, so ages were left as they are; age leaderboards spanning 2009-10 mix the two conventions by up to a year. The Breakout Detector's tooltip says so.
- **No EPM, RAPM or other proprietary/plus-minus impact metric.** EPM is proprietary and isn't used or imitated anywhere. Every "offensive quality" weight in the advanced-analytics features (DAD Index, Spacing Lab validation, Contract Value's WAR) comes from Basketball-Reference's published BPM/OBPM/VORP (since 2026-09-27; before that, this project's own BPM 2.0 reproduction, which ran hot). The reproduction survives only as `*_repro` columns feeding Pair Synergy's trained model.
- Scouting Report has no pick-and-roll coverage type or drive direction at all (not in any real dataset this project uses). Its closest-defender / touch-time / dribble splits (v2) cover 3PT only — 2PT bands mix layups with mid-range jumpers, so they'd mostly restate where a player shoots. At p < 0.05 about 1 in 20 tested splits clears the bar by chance; the card always shows that expected count. Play-type significance rests on an estimated per-possession SD (Synergy publishes no per-possession outcomes). "Toughest defenders" samples are small (10+ shots) and descriptive.
- Gravity is a composite proxy from tracking *splits*, not true gravity (how far defenders shade toward a player off the ball) — that needs raw defender coordinates, which aren't public. The Spacing Lab's predicted ORtg change is a real across-lineup association with a modest effect size, not a forecast for any specific lineup, and is withheld outside the range of real lineups. `lineup_stats` stores each season's 2,000 most-used lineups (the endpoint's cap), so very rare lineups aren't on file.
- **Contract Value salary data is third-party and imperfect — read before trusting a number.** The two salary CSVs are Kaggle uploads the owner downloaded (a 2000–2020 file and "NBA Player Stats and Salaries 2010-2025"), built by their uploaders from HoopsHype and Basketball-Reference, with no stated license — so they're kept local in `nba_data/salaries/` (gitignored, not redistributed); to rebuild, download them into that folder as `nba_salaries_2000_2020.csv` and `nba_player_stats_salaries_2010_2025.csv`, then run `load_salaries.py` and `build_contract_value.py` (the Contract Value smoke test skips if they were never loaded). Problems found by checking against real contracts: the 2010–2025 file's 2020-21 to 2023-24 salaries are inflation-adjusted (every player scaled by the same factor per season, e.g. ×1.156 for 2021-22), so those seasons are excluded rather than reconstructed; the 2000–2020 file's 2000–2005 payrolls are incomplete (excluded), it repeats stale rows for retired players (e.g. Cuttino Mobley at $9.5M through 2012-13 — why only players who actually played are priced, making cost per win the price of on-court production rather than total spending, with dead money and injured players left out), its 2017-18 is missing major players (excluded by the 90% minutes-coverage gate), and some individual rows are wrong (both files list Stephen Curry 2017-18 at his 2018-19 salary). Scraping the sources directly isn't possible: Basketball-Reference sits behind a Cloudflare bot challenge and its terms forbid automated collection, and HoopsHype's robots.txt blocks AI agents by name. WAR depends on this project's VORP reproduction (rescaled to real wins, not replaced by Basketball-Reference's numbers). No minimum-contract label is inferred (the full years-of-service scale isn't sourced for every season).
- `player_shots` includes real playoff (`game_id` `004…`) and play-in (`005…`) shots alongside the regular season (`002…`); anything computing regular-season shooting from it must filter on `game_id`. Separately, every bulk-loaded row has a NULL `shot_zone_basic`, so zones always come from `shots_lib.classify_zone()`'s coordinate rule — corrected 2026-09-26 (see Just shipped).
