1) HIGH-LEVEL ARCHITECTURE
================================================================================
  - Frontend: React 19 + Vite 8, dark dashboard UI, Axios to three backends.
  - Backend: Three separate FastAPI apps (microservices), each with CORS (*).
  - Database: PostgreSQL database name "nba_analytics" (player_season_stats,
    season_similarity, career_similarity, mvp-related tables per PROJECT_DETAILS.md).
  - Live data: nba_api (Python), NBA CDN JSON, optional BallDontLie standings,
    TheSportsDB (badges, player images), RSS + optional RapidAPI for news.
  - ML: Logistic regression MVP (.pkl), similarity precomputed in DB, impact
    scores stored in player_season_stats.

  Service layout (MUST match frontend/src/services/api.js):
    MVP API        → http://localhost:8000
    Similarity API → http://localhost:8001
    Impact API     → http://localhost:8002
    Vite dev       → http://localhost:5173 or http://127.0.0.1:5173

  NOTE: The `if __name__ == "__main__"` blocks inside mvp_api.py and
  similarity_api.py use different default ports than above. Always start with
  uvicorn and explicit --port 8000 / 8001 / 8002 to match the frontend.

  2026-09-21 — BPM & VORP (Box Plus/Minus, Value Over Replacement Player) —
    the "holy grail all-in-one metric" from the user's advanced-metrics
    wishlist. Basketball-Reference blocks automated fetches of their own
    methodology page, so this is an independent REPRODUCTION of the
    published BPM 2.0 formula (Daniel Myers), sourced from a verified
    working open-source reimplementation (jonahmiller99/basketball-utils
    on GitHub) rather than guessed — same "verify, don't fabricate a
    proprietary formula" rule this session has followed throughout
    (contrast with EPM/DARKO/LEBRON/RAPTOR, ruled not implementable
    earlier this session for exactly this reason — those have no public
    formula at all to reproduce).
    - scripts/add_personal_fouls.py (NEW) — additive migration adding `pf`
      (personal fouls), a required BPM input this table never had. Already
      sitting unused in the same historical CSVs everything else was built
      from (100% coverage, all 17 seasons, zero new fetch needed).
    - scripts/build_bpm_vorp.py (NEW, by far the most implementation-
      intensive script this session) — builds team-season aggregates from
      player_season_stats (this table only has player-level data, so
      "team totals" needed constructing from scratch), estimates each
      player's position and offensive role via the official 3-pass-
      trimmed regressions, interpolates BPM/OBPM coefficients between the
      Pos_1/Pos_5 tables, and calibrates each team's raw BPM to match
      their real net_rating (documented simplification: no opponent-
      adjusted SRS-style rating and no game-log-level "lead bonus" term,
      since this project has neither).
    - Four real, verified bugs found and fixed through actual diagnostic
      work (not assumed away), in the order discovered:
        1. OBPM calibration target was off_rating's ABSOLUTE scale
           (~110) instead of re-centered against league average — every
           player's OBPM was inflated by ~100+ points. Fixed by computing
           a league-average off_rating per season and subtracting it.
        2. Individual player POSS was mistakenly multiplied by games-
           played again in the team-aggregate step, even though it's
           already a season total (confirmed earlier against a real
           LeBron James row) — inflated team-level pace ~70x.
        3. The "position_adjustment" term (a real component of the
           official formula, including an offensive-role-slope penalty
           that corrects for high-usage volume scorers) was missing
           entirely from the first implementation.
        4. The biggest one: entire team rosters were clustering to nearly
           identical BPM values (Nikola Jokić ranking BELOW his own deep
           bench — literally below a player averaging 10 minutes/game),
           traced to a wrong assumption that individual POSS sums to 5x
           the team's real total (usage-based attribution). It doesn't —
           nba_api's POSS is already "team possessions while this player
           was on the floor" (same on/off-court convention as this
           table's other per-100-poss columns), so no team-pace
           conversion was needed at all — using it directly was correct
           from the start. Verified by checking the ratio empirically
           before committing to the fix, not just theorizing.
      Iterated through two more failed hypotheses (a literal "/5" reading
      of the reference formula's team-adjustment step, and a manual
      component-by-component comparison between Jokić and Shai Gilgeous-
      Alexander) before landing on the real cause — both dead ends are
      left out of this changelog's blow-by-blow, but the discipline was:
      test a concrete, falsifiable hypothesis against real players every
      time, not tweak coefficients and hope.
